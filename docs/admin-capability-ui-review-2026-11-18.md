## 能力纠错规则

使用已有 `feature` override：文本 / 文本·视觉 / 向量 / 图片。现有 OpenAI
适配器支持的类型才出现；不为 TTS、视频等增加空选项。图片的生图与编辑保持两个
独立布尔值和独立验证证据；切到非图片类型显式清除两项图片能力。保存类型时由
界面填写原有 operator source/revision，不要求管理员再维护登记版本。
目录刷新不会覆盖已选值；草稿立即影响短标签和筛选。旧目录图片声明、视觉标签
不能把手动文本/向量纠错再改回去。价格、上下文与原传输身份保留。
能力草稿未保存时禁止以该模型入口启动测试，避免测试服务器旧配置却误认新草稿
已验证；无关显示名/其他型号草稿不阻断已保存型号测试。

## 工作审视报告

原定目标：管理员能纠正目录缺失能力并选择正确型号，减少完成任务所需的阅读和
点击；验证状态由原运行证据所有者维护。

| 问题 | 根因 | 改正 |
| --- | --- | --- |
| 所有型号都出现图片专用入口 | 按当前缺失图片编辑的实现细节组织操作，没有抽象回“模型元数据纠错”这个任务 | 复用详情与已有 feature 字段，按类型展示必要控件 |
| 每行反复解释图片启用与验证 | 将边界提示当成每条记录状态，增加比较成本 | 短标签表示能力，验证提示在工具区只出现一次 |
| 两个批量动作与两个日常筛选单独折叠 | 机械把“次要”理解成“必须隐藏” | 根据频率与操作成本判断，保留确认但取消额外 disclosure |
| 配置范围与后续诊断入口藏在详情 | 只按内容长度判断，而非按决策用途 | 适用任务、运行状态与链接常显，原始证据按需 |

保留的有效约束：目录声明不等于验证、旧接口身份兼容、草稿保护、危险操作按需、
范围外流程不随视觉整理改变。后续先问“此信息是否影响当前判断/高频动作”，再
决定是否折叠；不能仅按字段数量或“高级”命名决定。
