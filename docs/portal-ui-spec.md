# Portal UI Spec（客户门户）

> 供用户确认的布局与披露约定。对齐近期密度 / 导航 / 账号商业入口决策。  
> **不**引入新的 admin 式视觉治理门禁。

---

## 1. 目标

- **先信任、再办事**：默认安静；有事才出黄条 / 徽章 / 状态卡。
- **一眼能行动**：标题行或告警行右侧放主 CTA，少让用户在空栏里找按钮。
- **少重复**：同一状态只在一处说一次（含容量 / 连接 / 额度）。
- **信息架构（IA）**：
  - **账号** = 身份 + 购买（管理套餐 / 支付订单在账号页）。
  - **套餐** = 短额度看护页（数字 + 有事才告警 + 链到账号升级）；勿把管理套餐/订单搬回套餐页。
  - **服务状态**有问题才出，平时隐藏（首页为主；站点详情同原则）。
  - **工单**是导航一级入口，但首页以「我的站点」为主，不并排抢版。
  - 顶栏不露登录身份；右上仅明文「退出」，无头像下拉。

## 2. 布局 Token

| Token | 约定 |
|-------|------|
| 首页 / 站点详情内容宽 | **~880–920px**（`max-w-[56rem]`，居中）；两侧空白视为页边距；勿为填空加装饰 |
| 全局内容宽 | **`--portal-content-max-width: 80rem`** 保留；套餐/账单宽表可用 |
| Header | 无 `contextPanel` 时 **单列 stack**（`data-portal-header-layout=stack`）；描述全宽，禁止预留空右列 |
| 行高 | `--portal-row-min-height` 等现有 portal shell；站点表标题与表间距约 **8–12px** |
| 套餐页密度 | 权益卡与用量行：**簇集数字**（相关指标紧挨，勿 `justify-between` / 等分三列撑满宽）；卡内 padding 约 **12–14px**、行内约 **10–12px**、分组 `space-y` 约 **12px**（可紧、勿挤）；黄条 `w-fit` + 文案与 CTA **紧邻**（文案可 `max-w-prose`）；「查看站点用量明细」贴文字库行标签旁或标签/用量同一簇，勿进度条下单独右漂 |
| 按钮层级 | 站点行仅主按钮「打开站点」图标可见；**WP 后台 / 停用 / 移除进 ⋯**；连接新站点 +/- 切换；容量「查看套餐」为图标 CTA |

## 3. 渐进披露

| 元素 | 何时出现 |
|------|----------|
| Header 状态徽章 | **仅当**首页无注意力卡 **且**「我的站点」卡顶无容量告警；卡顶有容量告警时标题旁不挂同因黄徽（如「多个容量需要处理」）；正常态由 `PortalStatusBadge` 隐藏 |
| Service Status / 注意力卡 | **仅当**有可展示内容（注意力 / 证据行 / 加载失败 / 重检提示 / 额度行等）；**安静默认整卡不渲染**（含站点详情空「服务状态」壳） |
| 告警行 | 非容量项：`w-fit` 左对齐；**容量告警进「我的站点」卡顶**；容量行两行：上行标题+CTA，下行 detail（勿 ⓘ） |
| 容量 / 连接黄条 | 站点详情：主问题收进 **`#service-status` 内**黄条 + 可见说明 + 明文 CTA（勿漂浮；勿与「服务运行」同因双黄）；额度压力勿双黄；首页多容量合并为一行摘要 |
| 指标条 | 首页 **metrics rail** 进标题行右侧（`metricsPlacement="title-end"`）；勿等分三列撑空；勿为填空占满右栏 |

## 4. 共用原语

- `PortalWorkspaceHeader` — 标题 / 元信息 / metrics；`metricsLayout="rail"` 用于首页
- `PortalMetricStrip` — `layout: grid \| rail`
- `PortalRowActions` — 行内主/次/⋯；危险确认
- `PortalPageState` / `PortalLoadingState` — loading / empty / error / ready；**页级与会话加载用骨架屏**（`PortalLoadingState` 或 Suspense 的 `LoadingFallback`），禁止 ⏳ / 沙漏居中
- `PortalStatusBadge` / `PortalStatusInline` — 正常态收敛
- `PortalAccountCommercePanels` — 账号页：管套餐 / 买额度 / 试用 / 支付订单
- `PortalNavbar` — 主导航含「服务 / 套餐 / 用量 / 工单 / 账号」；右侧仅明文 **「退出」文本按钮**，无头像下拉、无仅图标
- `PortalBreadcrumb` — 标题上方安静路径：站点详情 `服务 / 我的站点 / 当前站点`；套餐页 `服务 / 套餐`（可点段进对应路由；当前段不可点）
- `PortalInfoHint` — 长说明收进 ⓘ（套餐介绍 / 共享额度 / 知识容量分组说明等）

## 5. 分页面意图

| 页 | 意图 |
|----|------|
| **首页** | 以「我的站点」为主（工单仅导航、不并排抢版）；窄带 `56rem`；指标靠标题行右；无冗余 eyebrow；**无待办时不渲染注意力/服务状态黄条**；有待办时单表面 `w-fit`；容量告警进「我的站点」卡顶时标题旁不挂同因黄徽；「连接新站点」；站点 **短 URL 同行** |
| **站点列表** | 标题仅「我的站点」（无「N 站点」计数）；name\|短 URL 同行；容量告警卡顶；连接指引在按钮下；⋯ 不裁切 |
| **站点详情** | 标题上方完整面包屑 **`服务 / 我的站点 / 当前站点名`**（`服务`→`/portal`，`我的站点`→`/portal#sites`，当前段为显示名不可点）；同首页窄带 `56rem`；无 `contextPanel` 空右列；**注意力收进 `#service-status` 内**（`w-fit` 黄条：**可见说明** + **明文 CTA**；仅 Cloud Addon 基线缺上报时黄条（可选插件不警告）；主 CTA 为联系支持、重检为次要，并写出插件名）；同一非知识 `action_required` **不得**在「服务运行」再挂第二枚黄徽「需要关注」（改中性「见上方说明」）；重检结果只出现一次；徽章 ⊕ 注意力互斥；短 URL；标题行铅笔改名与 ⋯ 紧挨标题（勿 `ml-auto`；WP 后台/移除进 ⋯）；证据行左对齐紧凑簇；站点知识分级文案（软问题徽章「知识库可用」；硬失败才「更新失败」）；**介绍句「站点知识帮助 AI…」不常驻正文，收进标题旁 ⓘ**；**偶发更新未成功说明不常驻正文、也不进标题 ⓘ，仅收进「最近更新」指标旁 ⓘ**（与指标 ⓘ 同交互）；缺插件 Portal 只警告 Cloud Addon 基线；「明确错误事件」仅在 count>0 时显示；**无待办时不渲染空「服务状态」卡**；指标满宽 grid + 图标刷新 |
| **套餐（billing）** | 面包屑 **`服务 / 套餐`**（`服务`→`/portal`）；短标题「套餐」；套餐名 + 账期进标题行右侧 metrics rail（`title-end`，同首页）；无额度压力时不渲染告警表面，「管理套餐」作次要 CTA；有压力：告警收进权益卡顶 `w-fit`（**可见一行说明** + **明文 CTA** 紧邻文案：买额度 / 升级），**勿** Header `contextPanel` 黄卡或同因黄徽；**黄条已覆盖的 limited 同因**：权益行不挂「需要关注 / 已超限」红徽、进度条用中性填充（勿报警红）、行下橙字溢出说明不重复（数字如 2/1、超限计数仍可读）；接近上限（near_limit）且黄条未覆盖时仍可保留观察态；**密度**：权益行标签与主数字同簇（勿左右钉死留大空洞）；AI 积分子项（本期剩余 / 付费余额 / 可用）为紧凑簇而非满宽三列；容量行进度条可满宽，但「查看站点用量明细」贴文字库标签簇；卡/行 padding 与分组间距按 §2 套餐页密度；介绍 / 账号共享额度 / 知识容量长说明 → 标题或分组旁 ⓘ；管理与订单已迁出账号页；**支付回跳通知仍留本页**；宽表可用全局 80rem |
| **用量** | 用量与额度轨迹；升级链到账号 `#package-options` |
| **工单** | 列表 + 标题旁新建 CTA |
| **账号** | 登录联系 + **套餐与支付**（Manage package / Payment orders）；菜单「订单与账单」→ `#payment-orders` |

## 6. 禁止模式

- 空右列 / `xl:max-w-3xl` 半宽状态卡旁大片空洞  
- 同一告警在 Header + Service Status（或双黄额度）重复；首页卡顶已有容量告警时标题旁再挂「多个容量需要处理」等同因黄徽；站点详情注意力不得漂浮在 Header 与服务卡之间（须收进 `#service-status`）  
- 顶部注意力与「服务运行」对同一非知识问题各挂一枚「需要关注」黄徽  
- 站点详情注意力仅图标 CTA、无明文下一步；或缺插件上报却把「重新检查」当成能修好的主操作且不写出插件名  
- 站点知识仍可用（已有收录、多数更新成功）却一律标「更新失败」  
- 头像下拉第二套「账号 / 设置 / 订单 / 退出」（保留主导航「账号」+ 顶栏「退出」）  
- 首页告警默认展开长正文，或标题与 CTA 两端拉满留白  
- 强制 `md:grid-cols-3` 撑空指标格  
- 有站点时底部常驻「连接指引」与标题「连接新站点」文案重复  
- 注意力区 Section+Card+行边框多层描边；为填空加的空右列装饰  
- 危险「移除/停用」常驻行内无确认入口；操作列换行撑高  
- 站点详情全宽 `<details>其他操作` 单钮占一行（须 RowActions）  
- 为填空而加的装饰文案 / 空 aside  
- 站点详情在无注意力、无证据、无加载/重检失败时仍展示空「服务状态」标题壳  
- 站点知识区常驻介绍段落「站点知识帮助 AI…」（须收进标题旁 ⓘ）  
- 偶发「近 N 天有 M 次更新未成功…」常驻知识正文，或塞进标题旁 ⓘ（须只在「最近更新」ⓘ）  
- 页级 / 会话加载用 ⏳ 或沙漏居中「加载中」（须 `PortalLoadingState` / `LoadingFallback` 骨架）  
- 套餐页 Header `contextPanel` 黄卡旁空右列，或告警详情默认收进「详情」折叠（须可见一行说明 + 明文 CTA）  
- 无额度压力仍渲染套餐告警表面；有压力时 Header 再挂同因黄徽  
- 套餐页黄条已说明 limited 容量时，权益行再挂同因「需要关注 / 已超限」红徽、报警红进度条、或行下橙字溢出说明重复尖叫  
- 套餐介绍 / 账号共享额度说明 / 知识容量分组长说明常驻正文（须收进标题或分组旁 ⓘ）  
- 套餐权益行用 `justify-between` / 等分三列把标签与数字撑满宽留大空洞；AI 积分子项满宽三栏拉空；「升级套餐」与黄条文案两端拉满；「查看站点用量明细」孤悬进度条下最右侧

## 7. 验收清单

**桌面**

- [ ] 首页及门户页级加载为骨架屏（`PortalLoadingState` / `LoadingFallback`），无 ⏳ / 沙漏居中  
- [ ] 首页约 900 内居中；指标在标题行右；注意力单表面 `w-fit`；长描述默认隐藏  
- [ ] 无待办时无注意力表面；有待办时 `w-fit` 左对齐；详情仅 hover/focus  
- [ ] 徽章与注意力卡不同时抢同一状态；卡顶有容量告警时标题旁无同因黄徽  
- [ ] 我的站点：标题行「连接新站点」图标按钮；表贴标题；指引不与标题按钮常驻重复  
- [ ] 顶栏退出为 **明文「退出」文本按钮**（无头像下拉、无仅图标）；「账号」进账号页含订单/套餐  
- [ ] 站点详情：标题上方面包屑 `服务 / 我的站点 / 当前站点名`（前两段可点且目标正确）；`56rem`；无空右列；注意力在 `#service-status` 内 `w-fit` + **可见说明** + 明文 CTA；缺插件上报时写出插件名、主 CTA 联系支持、重检次要；服务运行不与注意力同因双黄；有明确错误时「联系支持」；**安静时不渲染空服务状态卡**（Header 仅徽章）；证据左对齐；知识分级（非硬失败勿「更新失败」）+ 介绍进标题 ⓘ、偶发更新说明仅在「最近更新」ⓘ、指标满宽；标题旁改名铅笔；改名输入须支持中文输入法（组字期间 Enter 不保存）  
- [ ] 套餐页：面包屑 `服务 / 套餐`；短标题；套餐名/账期在标题行右 rail；无压力无告警表面 + 「管理套餐」次要 CTA；有压力权益卡顶 `w-fit` 可见说明 + 买额度/升级明文 CTA（文案与 CTA 紧邻），无 Header `contextPanel` / 同因双黄；有压力时权益行对黄条已覆盖的 limited 同因无红徽 / 无报警红条 / 无行下橙字重复，数字仍可读；**密度**：标签与主数字同簇、AI 子项紧凑簇、无满宽三列空洞；「查看站点用量明细」贴文字库行；卡/行 padding 紧凑不挤；介绍与共享额度、知识容量说明进 ⓘ；支付回跳通知仍在本页  

**375 / 768**

- [ ] 告警行 CTA 可点、不横溢；指标 rail 可换行  
- [ ] 站点行：仅打开站点图标 + ⋯（WP 后台/停用/移除在菜单）  

**i18n**

- [ ] 关键文案 en + zh-CN 成对（含退出、连接新站点、详情、重试语义等）  

---

## 8. 范围外

- 不新增 admin 式 visual governance / receipt 门禁  
- 不强制全局从 80rem 改为 56rem（首页 + 站点详情窄带；其余页仍用全局 content max）  
- 不改 Alipay `payment_return` 仍落在 `/portal/billing` 的后端契约（可另迭代）  
- 不做本 Spec 未列的 IA 大迁（如整页账单搬迁已完成部分除外）  

---

## 9. 交付门禁 / 自检

改 Portal UI 后，**agent 交付前必须**：

1. **m4 sync 之后**打开预览：`http://127.0.0.1:18010/portal`（及本次改动的路由，含 `/portal/sites/[siteId]` / `#service-status`、`/portal/billing`）。
2. **目视对照**本 Spec §7 验收清单（桌面 + 相关断点），不只看代码。
3. **先修残留**（空栏、套娃描边、危险操作暴露、换行撑高等），再向用户报告「完成」。
4. **仅 contracts / type-check 绿 ≠ 交付**；无预览目视不得宣称 UI 已交付。
