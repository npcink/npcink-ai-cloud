# Portal UI Spec（客户门户）

> 供用户确认的布局与披露约定。对齐近期密度 / 导航 / 账号商业入口决策。  
> **不**引入新的 admin 式视觉治理门禁。

---

## 1. 目标

- **先信任、再办事**：默认安静；有事才出黄条 / 徽章 / 状态卡。
- **一眼能行动**：标题行或告警行右侧放主 CTA，少让用户在空栏里找按钮。
- **少重复**：同一状态只在一处说一次（含容量 / 连接 / 额度）。
- **信息架构（IA）**：
  - **账号** = **登录与安全** + **支付订单**（身份与订单；**勿**放升级套餐 / 买积分 / 试用 CTA）；**勿**与套餐/用量合并进顶栏。
  - **套餐（站点用量进 Modal）** = 顶栏**单一入口**（文案 **「套餐」**）。标题行右 **metrics rail**；主滚动磁贴（无「额度」大标题；可选「本套餐可用」）；AI 积分同知识库：`已扣/(已扣+可用)` + `剩余: 可用` + 进度条（主比例可点→轻量「获取来源」弹窗）；软副标「查看本期用量」滚到页内**站点用量列表**；点站点 → **站点用量 Modal**（趋势 / AI 积分记录）。**升级 / 管理套餐 / 买积分 / 试用仅在本页对话框**；支付订单在账号页。
  - **服务状态**有问题才出，平时隐藏（首页为主；站点详情同原则）。
  - **工单**是导航一级入口，但首页以「我的站点」为主，不并排抢版；**勿**与套餐合并。
  - 顶栏不露登录身份；右上仅明文「退出」，无头像下拉。
  - **深链**：`/portal/usage`、`/portal/billing#usage`、`#site-usage` → 打开套餐页并**滚到站点用量列表**（`#site-usage`；保留 query）；旧书签不可断。

## 2. 布局 Token

| Token | 约定 |
|-------|------|
| 用户服务中心内容宽 | **统一 ~880–920px**：`--portal-content-max-width: 56rem`（`portal/layout` → `.portal-content`）；**概览（`/portal`）为参照**；套餐 / 账号 / 工单 / 站点详情等同壳，勿单独加宽或收窄；两侧空白为页边距 |
| 顶栏内行宽 | 顶栏 **背景可通栏**（full-bleed）；**内行**（logo + 主导航 + 语言/主题/退出）与正文同列 **`max-w-[var(--portal-content-max-width)]`（56rem）居中**，左右 padding 与 `.portal-content` 对齐。目标态：**导航内行不得宽于内容列**；内行已与内容列对齐（见 §10） |
| 套餐容量黄条 | **对齐概览「我的站点」容量条**（`PortalSitesWorkspace` `data-portal-sites="capacity-alerts"`）：黄条表面 **`w-full`** 铺满内容列；行内标题区 `flex-1` + CTA `shrink-0`；**正文描述**加 **`max-w-md`**（28rem / 448px）提前换行，勿一行拉到 CTA；**禁止**对黄条表面用 `w-fit` / `max-w-prose` 收成半宽留白 |
| Header | 无 `contextPanel` 时 **单列 stack**（`data-portal-header-layout=stack`）；描述全宽，禁止预留空右列 |
| 行高 | `--portal-row-min-height` 等现有 portal shell；站点表标题与表间距约 **8–12px** |
| 套餐页密度 | 标题「套餐」+ metrics rail；主列无「额度」大标题（软副标可选）；两列磁贴；AI 积分对齐图片库：主 `已扣/(已扣+可用)`、旁 `剩余: 可用`、同款进度条；主比例→「获取来源」Modal（`size="2xl"`）；「查看本期用量」→滚到站点用量列表；点站点→站点用量 Modal（趋势/记录，`size="2xl"`）；无空壳 included、无同值三行；黄条 `w-full`；页头对齐工单紧凑 chrome；无可见 commerce 不占 space-y；**单站**满宽 + 安静副文案（不自动弹窗） |
| 按钮层级 | 站点行仅主按钮「打开站点」图标可见；**WP 后台 / 停用 / 移除进 ⋯**；连接新站点 +/- 切换；容量「查看套餐」为图标 CTA |

## 3. 渐进披露

| 元素 | 何时出现 |
|------|----------|
| Header 状态徽章 | **仅当**首页无注意力卡 **且**「我的站点」卡顶无容量告警；卡顶有容量告警时标题旁不挂同因黄徽（如「多个容量需要处理」）；正常态由 `PortalStatusBadge` 隐藏 |
| Service Status / 注意力卡 | **仅当**有可展示内容（注意力 / 证据行 / 加载失败 / 重检提示 / 额度行等）；**安静默认整卡不渲染**（含站点详情空「服务状态」壳） |
| 告警行 | 非容量项：`w-fit` 左对齐；**容量告警进「我的站点」卡顶**；容量行两行：上行标题+CTA，下行 detail（勿 ⓘ） |
| 容量 / 连接黄条 | 站点详情：主问题收进 **`#service-status` 内**黄条 + 可见说明 + 明文 CTA（勿漂浮；勿与「服务运行」同因双黄）；额度压力勿双黄；首页多容量合并为一行摘要 |
| 指标条 | 首页 **metrics rail** 进标题行右侧（`metricsPlacement="title-end"`）；勿等分三列撑空；勿为填空占满右栏 |
| 套餐权益释义 | 各资源长说明、套餐介绍、共享额度、知识容量分组说明：**默认折叠**，仅 ⓘ hover/focus 展开；勿在磁贴正文常驻多行释义 |

## 4. 共用原语

- `PortalWorkspaceHeader` — 标题 / 元信息 / metrics；`metricsLayout="rail"` 用于首页
- `PortalMetricStrip` — `layout: grid \| rail`
- `PortalRowActions` — 行内主/次/⋯；危险确认
- `PortalPageState` / `PortalLoadingState` — loading / empty / error / ready；**页级与会话加载用骨架屏**（`PortalLoadingState` 或 Suspense 的 `LoadingFallback`），禁止 ⏳ / 沙漏居中
- `PortalStatusBadge` / `PortalStatusInline` — 正常态收敛
- `PortalAccountCommercePanels` — `surface=account`：支付订单；`surface=billing`：套餐/额度/试用对话框（无账号页套餐摘要行）
- `PortalNavbar` — 主导航：**「服务 / 套餐 / 工单 / 账号」**（无独立「用量」项）；右侧仅明文 **「退出」文本按钮**；内行宽对齐 56rem（见 §2）
- `PortalBreadcrumb` — **仅深度 ≥ 2**（次级及以下）在标题上方画安静路径；**顶栏一级页**（套餐 `/portal/billing`、工单列表 `/portal/support`、账号 `/portal/account`、首页 `/portal` 等）靠导航高亮 + 页面标题定位，**不**再画面包屑。次级路径从**各自一级导航同伴**起算，勿把同为顶栏一级的「工单 / 账号」再挂到「服务」下：站点详情仍为 `服务 / 我的站点 / 当前站点`（服务=首页/站点工作区）；工单详情 `工单 / 标题`；最近活动 `账号 / 最近活动`。站点用量在 Modal 内，无单独 PortalBreadcrumb 段
- `PortalBillingSiteUsageList` — 套餐页站点用量列表（默认展示站点）；点站点开 `PortalSiteUsageDialog`
- `PortalSiteUsageDialog` — 站点用量 Modal：趋势 / AI 积分记录；详情在同 Modal 内返回，不叠第二层抽屉

#### 站点用量弹窗布局

- 固定高度 `h-[min(90vh,48rem)]`，内容区内部滚动；顶部 sticky 头 = 摘要行 + Tab，滚动时不丢失。
- **单一时间范围**（1 小时 / 24 小时 / 7 天 / 30 天）放在 Tab 上方、与摘要同一行（左摘要 + ⓘ（ⓘ 与末词 nowrap 粘连，不单独换行），右范围），趋势与积分记录共用；积分记录 1 小时用显式 `start_at/end_at`。Tab 内不再各自放范围控件。范围控件为轻量分段文字按钮（无灰底块，选中=加粗深色），文案「1 小时 / 24 小时 / 7 天 / 30 天」，右对齐并与摘要行垂直居中。仅面向 PC。
- 单位统一写「AI 积分」；拼接「 · 更新于 …」一律走 `joinSummaryParts`，去掉片段末尾的 `。` 等标点，不出现「。 ·」。
- 趋势图：嵌入时无卡片边框、无重复摘要；顶部虚线标注「峰值 N AI 积分」，悬停柱子显示「时间 · N AI 积分」；0 值桶显示浅色基线（不留空洞）；X 轴末标签右对齐，与其相距不足一个间隔的常规标签省略，窄屏不得粘连。
- 积分记录表：`table-fixed`，列 = 时间 / 服务 / AI 积分（单位只写在表头，单元格只放数字）/ `›`；整行可点进入详情，无「操作」列和「查看详情」按钮；列内边距 `px-2 py-3`；服务名长文本换行（`break-words`），时间与数字不换行。
- **按天分组（7 天 / 30 天）**：积分记录默认按本地自然日一行（日期 / 调用次数 / 合计 AI 积分 / `›`），无调用的日子置灰不可展开；点日期行原地展开当天全部调用（时间精确到分钟，沿用时间/服务/AI 积分/`›` 列，整行点开详情）；按天分页（每页 10 天）。日期行数据来自 `GET /portal/v1/account/credit-event-days?window=7d|30d&tz=<IANA>&site_id&feature&limit&offset`（按本地自然日聚合，**每页 1 个请求**，含零值日以保证按天分页稳定；受会话所选站点约束，否则 409）；日期行在调用次数旁用小字列出按服务拆分（前两项 + 其他）。展开当天仍用 `credit-events`（`start_at/end_at`，50 条一页取全）。1 小时 / 24 小时为逐条平铺列表。服务类型筛选收进表头（逐条表「服务类型」列 / 按天表「服务构成」列），无表头时用紧凑回退；作用于两种模式。
- **图表联动**：点趋势柱子切到积分记录并按该柱时间窗过滤为逐条列表，显示可移除的时段筛选 chip（如「10/20 18:00–19:00 ×」）；切换时间范围或点 × 清除。
- 分页 sticky 在底部，单页也显示「1–N / 共 N」与上一页/下一页（禁用态）。
- `PortalCreditSourcesDialog` — 获取来源 Modal（点积分卡主比例）
- `PortalInfoHint` — 长说明收进 ⓘ（套餐介绍 / 共享额度 / 知识容量分组说明 / **各权益资源释义** / 站点用量趋势说明；默认折叠）

## 5. 分页面意图

| 页 | 意图 |
|----|------|
| **首页** | 以「我的站点」为主（工单仅导航、不并排抢版）；窄带 `56rem`；指标靠标题行右；无冗余 eyebrow；**无待办时不渲染注意力/服务状态黄条**；有待办时单表面 `w-fit`；容量告警进「我的站点」卡顶时标题旁不挂同因黄徽；「连接新站点」；站点 **短 URL 同行** |
| **站点列表** | 标题仅「我的站点」（无「N 站点」计数）；name\|短 URL 同行；容量告警卡顶；连接指引在按钮下；⋯ 不裁切 |
| **站点详情** | 标题上方完整面包屑 **`服务 / 我的站点 / 当前站点名`**（`服务`→`/portal`，`我的站点`→`/portal#sites`，当前段为显示名不可点）；同首页窄带 `56rem`；无 `contextPanel` 空右列；**注意力收进 `#service-status` 内**（`w-fit` 黄条：**可见说明** + **明文 CTA**；仅 Cloud Addon 基线缺上报时黄条（可选插件不警告）；主 CTA 为联系支持、重检为次要，并写出插件名）；同一非知识 `action_required` **不得**在「服务运行」再挂第二枚黄徽「需要关注」（改中性「见上方说明」）；重检结果只出现一次；徽章 ⊕ 注意力互斥；短 URL；标题行铅笔改名与 ⋯ 紧挨标题（勿 `ml-auto`；WP 后台/移除进 ⋯）；证据行左对齐紧凑簇；站点知识分级文案（软问题徽章「知识库可用」；硬失败才「更新失败」）；**介绍句「站点知识帮助 AI…」不常驻正文，收进标题旁 ⓘ**；**偶发更新未成功说明不常驻正文、也不进标题 ⓘ，仅收进「最近更新」指标旁 ⓘ**（与指标 ⓘ 同交互）；缺插件 Portal 只警告 Cloud Addon 基线；「明确错误事件」仅在 count>0 时显示；**无待办时不渲染空「服务状态」卡**；指标满宽 grid + 图标刷新 |
| **选择套餐 Modal** | Modal `size="3xl"` → **`max-w-3xl`（~48rem）**；三卡横排收紧间距；对比表列 padding 紧凑。卡面 CTA「选 Plus/选 Pro」；底栏「确认并继续」/支付动作在选定后启用（勿双主 CTA）。Free 当前无购买 CTA。未选态底栏弱化（勿大块禁用蓝条）。「仅显示差异」仅在对比表存在同值行时显示（否则隐藏并清掉勾选）；默认不勾。页脚仅条款/隐私，工单不进购买路径；Agency 报价折叠降级。价格按月付文案（如 ¥15/月）。 |
| **套餐（站点用量 Modal）** | 顶栏「套餐」→ `/portal/billing`；**无一级面包屑**。短标题+metrics rail；两列磁贴；AI 积分同知识库版式（主比例→获取来源 Modal）；「查看本期用量」→滚到站点用量列表；点站点→站点用量 Modal（趋势/积分记录）；Modal `size="2xl"`（约 `max-w-4xl`）。 |
| **工单** | 列表（**无一级面包屑**）；标题行 `actionsPlacement="title-end"`：左「工单」+ⓘ，右状态 chip + 提交；**无**底栏状态图例。列表/详情状态胶囊**始终可见**（`PortalStatusBadge force`，勿被站点「正常静默」吃掉「已解决」）。详情：面包屑 `工单 / 标题`、无重复 H1；气泡 L/R（**无**「你/客服」字标，靠左右色区分；时间默认隐藏，hover/focus 在气泡上方小字显示）；`rounded-2xl` composer 壳 `[附件][输入(内嵌刷新)][发送]`；**回形针直接打开系统选文件**（可多选；选完即上传，composer 旁 chip + ⓘ 格式说明；**勿**再出「选择文件 + 上传附件」第二层）；重开灰字右齐；关闭评价：未提交时窄卡 ~30rem 居中（分段拉满 + 五星 + 矮说明 + 主钮右齐）；**已提交后收起**，顶部绿条「评价已提交」即可，可选小链「更新评价」再展开；已关闭工单仍保留线程 + composer（回复/重开） |
| **账号** | **无一级面包屑**；标题行右「最近活动」`title-end`。单一「登录与安全」卡：邮箱主行 + 行内「修改邮箱」次要钮；登录方式（QQ 等）同卡；勿再拆「登录/联系方式」双标题。**勿**再放「套餐与支付 · 当前套餐」摘要行或「升级套餐」（升级仅在套餐页 / 套餐对话框）。保留支付订单（空态一行灰字，勿胖手风琴）+ 登录与安全 + 最近活动 |
| **最近活动** | 面包屑 `账号 / 最近活动`；**站点筛在表头**（时间列旁下拉，勿独立「站点筛选」卡）；表体分页默认 ~20/页，底栏 sticky「起止 / 共 N」+ 上一页/下一页（全部站点同样分页） |

### 5.x 站点绑定页（WordPress 插件跳转）

入口保持插件契约：`/portal?connect=wordpress-addon&site_url&site_name&return_url&state`（登录后原样回跳）。面向普通站长，必须极简：

- 只显示：标题「把这个站点绑定到你的账号」、一句白话说明（绑定后使用账号的套餐和 AI 积分）、站点名称/网址、账号名称（无名称时用登录邮箱，多账号时用「账号 N」）、唯一按钮「完成绑定」。
- 不显示：账号 ID（`acct_…`）、站点数量、归属/冷却等术语段落、显示名输入框、取消按钮、顶部导航和站点工作台（无 dashboard chrome）。
- 单账号：自动选中（#1172 `resolveDefaultAddonAccountId`），点击「完成绑定」即为明确确认。
- 多账号：纯文字单选列表，只列账号名称，不预选未确认的账号以外的默认值。
- 跨账号冲突/冷却仍由后端错误文案在提交后说明；加载失败、请求过期保留重试/从 WordPress 重新开始的提示。

## 6. 禁止模式

- 空右列 / `xl:max-w-3xl` 半宽状态卡旁大片空洞  
- 同一告警在 Header + Service Status（或双黄额度）重复；首页卡顶已有容量告警时标题旁再挂「多个容量需要处理」等同因黄徽；站点详情注意力不得漂浮在 Header 与服务卡之间（须收进 `#service-status`）  
- 顶部注意力与「服务运行」对同一非知识问题各挂一枚「需要关注」黄徽  
- 站点详情注意力仅图标 CTA、无明文下一步；或缺插件上报却把「重新检查」当成能修好的主操作且不写出插件名  
- 站点知识仍可用（已有收录、多数更新成功）却一律标「更新失败」  
- 头像下拉第二套「账号 / 设置 / 订单 / 退出」（保留主导航「账号」+ 顶栏「退出」）  
- 首页告警默认展开长正文，或标题与 CTA 两端拉满留白  
- 强制 `md:grid-cols-3` 撑空指标格  
- 有站点时底部常驻「连接指引」与标题「连接新站点」文案重复  
- 注意力区 Section+Card+行边框多层描边；为填空加的空右列装饰  
- 危险「移除/停用」常驻行内无确认入口；操作列换行撑高  
- 站点详情全宽 `<details>其他操作` 单钮占一行（须 RowActions）  
- 为填空而加的装饰文案 / 空 aside  
- 站点详情在无注意力、无证据、无加载/重检失败时仍展示空「服务状态」标题壳  
- 站点知识区常驻介绍段落「站点知识帮助 AI…」（须收进标题旁 ⓘ）  
- 偶发「近 N 天有 M 次更新未成功…」常驻知识正文，或塞进标题旁 ⓘ（须只在「最近更新」ⓘ）

- [ ] 服务中心内容列统一 ~56rem（壳层 `--portal-content-max-width`）；首页指标在标题行右；非容量注意力可 `w-fit`；长描述默认隐藏

## 9. 交付门禁 / 自检

改 Portal UI 后，**agent 交付前必须**（**不可跳过**；不得把「请用户看」当成自检）：

1. **m4 sync / deploy 之后本人打开预览**：`http://127.0.0.1:18010/portal` 及本次改动路由（至少含 `/portal/billing`；站点相关则含 `/portal/sites/[siteId]` / `#service-status`）。登录态不够时用静态对照 + 已部署 DOM/CSS 核对，仍须对布局项有证据。
2. **目视对照**本 Spec §7 验收清单（桌面 + 相关断点），**不只**看代码 / type-check / contracts。
3. **布局必查**（套餐 / 注意力相关改动时逐项打勾，未过先修再报）：
   - 内容列宽与概览一致（壳层 `56rem`）
   - 容量黄条表面 **`w-full`**（卡内无半宽留白）
   - 黄条**描述**有 **`max-w-md`（或等价，≤28rem）**、提前换行，未一行撑到 CTA
   - 无「数字左簇、右侧半卡空白」；权益用磁贴等填满
   - 长说明默认折叠（ⓘ），正文无常驻多行释义
   - 套餐主列无完整用量堆叠；站点列表 + 点站点 Modal；深链滚到 `#site-usage`；趋势长说明进 ⓘ；Modal 用正式 `size`（勿 className 覆盖 max-w）
4. **先修残留**（空栏、半宽黄条、描述一行拉满、套娃描边、危险操作暴露等），再向用户/父代理报告「可预览」或「完成」。
5. **仅 contracts / type-check 绿 ≠ 交付**；**未完成上述预览自检不得宣称 ready for user**。
