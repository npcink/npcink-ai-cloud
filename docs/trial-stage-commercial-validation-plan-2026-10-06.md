## 1. 目标与确认口径

用四周、首批 3 位实际写文章的站长验证使用价值、留存和成本，为是否进入邀请
收费阶段提供证据。免费试用不能证明购买意愿，购买意愿留到下一阶段验证。
观察一周后再决定是否扩到 5 位，新增用户单列，不改动首周队列。

本次确认覆盖最初的标题/摘要试用起点：

| 项目 | 本次确认 |
| --- | --- |
| 招募 | 首批 3 位定向介绍站长，正常自注册；不做邀请码、白名单或邀请管理 |
| 开户 | 邮箱验证注册或 QQ 首次登录；验证成功即获得账户级 Free |
| 额度 | 复用现有 Free，不新增试用套餐、周限额或周重置 |
| 代码基线 | 300 AI credits / 30 天周期，1 个站点；以实际账户权益显示为准 |
| 使用范围 | 当前官方 WordPress AI 插件经现有连接实际支持的能力，按写作需要自然使用 |
| 图像 | 仅按目标环境实际可用范围说明；文生图候选有预算覆盖但未新增真人验收，ALT视觉binding为空，不承诺可用；参考图编辑暂缓，不为本阶段补模型或改协议 |
| 支付 | 免费试用不付款、不充值、不自动转收费；不修改支付域配置 |
| 投入 | 不新增报表系统、埋点平台、试用管理后台，不为制造数据发起付费调用 |

Cloud 只拥有账户权益、运行与用量证据；WordPress 保留建议审阅、采纳、保存
和发布的最终真相。平台账单是成本侧真相，Cloud run 和 agent_feedback 是
行为侧证据，两者不能互相替代。

## 2. 三个假设与统计规则

| 假设 | 不变的判据 | 计算 |
| --- | --- | --- |
| H1 使用价值 | 采纳率 ≥40% | 可关联、去重的采纳事件 / 建议展示 |
| H2 持续使用 | 两周留存 ≥50% | 首周活跃种子中第二周仍真实使用人数 / 首周活跃种子人数 |
| H3 成本可承受 | 单活跃用户月成本 ≤¥5–7 | 对应拟议 ¥50–70/月价格的 10%，不改变现有售卖价格 |

H1 保留原生 agent_feedback 的 accepted、edited_before_accept 采纳证据，
按建议标识关联展示并去重。现有 summary 的 accepted_rate 是采纳反馈占
全部反馈，不能直接填入“采纳 / 展示”。编辑辅助 presented 事件、精确保存
匹配和人工记录分列来源；不得把生成完成、未匹配保存或人工确认冒充原生
采纳事件。无法确认展示或反馈覆盖时记录“证据不足”，不将缺失当拒绝。
需要启用的已有观测同意设置按现行规则处理，不为试用扩大采集。

H2 的真实使用是站长在正常写作中成功使用 AI 结果；仅登录、健康检查、
开发调用不算活跃。纯失败尝试单列为使用阻碍。固定首周种子队列；晚加入者
和其他自行注册者单列，不改动首周分母。首周无人活跃时 H2 不可计算。

H3 用第三方平台实际消费而非充值金额。优先按模型、输入/输出 token、
图片等实际计费单位归因；无法直接归因时，用各用户价格加权用量占比分摊
同类消费。仅有次数时采用次数比例并注明较粗估算。平台合计、试用分摊、
开发/自测与无法归属消费分别列示，不把未归属金额计为零。

- 周月成本估算 = 本周试用消费 / 本周活跃人数 × 30/7。
- 四周月成本估算 = 四周试用消费 / 四周活跃用户周数之和 × 30/7。
- 同时报告实际消费；零活跃时标记不可计算。
- ≤¥5 满足两个拟议价格档；¥5–7 仅满足较高价格档；>¥7 超出目标。
- 包含第三方实际计费的失败及重试，不能仅计算成功请求。

## 3. 种子、周期与周报

观察样本先为 3 位会真实写文章的熟人站长，名单由操作者受控保存。仓库中使用 S1–S3
等匿名标识；账户/站点映射由操作者受控保存，不提交邮箱、凭据或文章正文。
样本数量是观察队列大小，不是注册入口限制。

不预先指定 T+0；功能在实际试用环境可用且前置条件完成后，以实际邀请日
作为开始日期。时间统一 Asia/Shanghai，每周为固定半开区间：
第 N 周 [T+0 + 7(N−1) 天, T+0 + 7N 天)。查询转换为 UTC 后执行。

日常先通过现有云端运行、错误、额度和反馈数据观察；每周汇总这些证据，
启用付费 Provider 后再补充同一时间段的第三方消费明细，核对：

1. 各用户所属站点的 distinct run_id、能力使用、成功、失败和错误分类。
2. Provider 调用的模型、token、图片计费单位与平台消费；避免与 run 汇总重复累加。
3. 可关联展示与采纳、证据覆盖、人工补充和一个主要使用阻碍。
4. H1/H2/H3 的分子、分母、估算方法与判据比较；H2 在第二周正式核对，
   后续周相对首周的持续使用另列，不能冒充“两周留存”。

追加 docs/history/trials/<年>/trial-weekly-report-<第N周>-<日期>.md。
报告只记事实与估算，不提前下商业结论。没有明细或观测不完整时记缺口，
不生成虚构周报、不安排定时任务、不要求用户逐项测试所有能力。
