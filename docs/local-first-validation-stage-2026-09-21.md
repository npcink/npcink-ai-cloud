## 已确认的历史结论

### 技术链路

WordPress AI → Addon → Cloud → Provider → 返回编辑器的主要链路已经具备本地和 CI 验证证据。Addon 的 fake journey、显式保存边界、权限失败和并发标签页场景已有本地证据；Cloud 的主要合同和商业状态机已有测试覆盖。

这些证据只覆盖所记录的场景，不代表完整链路已经可靠。它们说明链路可以继续开发，不说明真实用户已经采用，也不说明生产环境已经获准发布。

### 支付

Cloud 代码同时支持模拟支付宝和已实现的真实支付宝适配器。默认仍是模拟模式，当前没有真实支付宝配置或真实收款证据。

支付宝回调必须经过 Cloud 验签和订单状态处理；浏览器 return 页不能证明支付成功。订单、支付事件、退款、AI credit grant 和退款 adjustment 具备唯一键、锁和幂等保护。真实沙箱下单、回调、退款和异常重放尚未执行。

微信支付仍是模拟/预留路径。现在启动微信只会扩大签名、证书、退款和对账维护面，不能提升当前本地验证价值，因此继续延后。

### Provider 成本

客户套餐价格、AI credits 和 Provider usage/cost 已在模型和文档中分开。Cloud 能记录运行和成本证据，也有本地 Provider call ledger，能够限制一次实验的调用次数。

目前没有统一的 Provider 账户级每日/月度成本硬上限、预算告警和供应商账户自动停止机制。这个缺口需要保留，但不作为操作者本人使用正式模型的前置开发项目。开发自动化测试与个人真实使用分别管理：前者优先确定性夹具、免费或本地模型，后者可以使用操作者自行选择和配置的正式模型，包括按实际用量付费的模型。

### 自然流量和质量

当前自然样本数为 0，七天观察窗口和 50 个真实样本门槛尚未开始。已有的 Cron、fake journey 和本地 Ollama 结果是技术证据，不应被写成真实用户价值证据。

开发者本人现在即可判断标题是否相关、摘要是否忠实、改写是否保真，并记录自己的采用或放弃；目前没有新增个人评审结果。规模化自然观察与外部用户评审留到需要它们的阶段。个人反馈可以证明所评场景的自身收益，不能代替外部市场或商业证据。

### 兼容性和发布

Addon compatibility matrix 最近连续运行通过，但曾出现第三方下载 `403` 后重跑通过的情况。因此当前不修改 branch protection，也不把 compatibility aggregate 设为 required。继续记录首轮失败和重跑结果，等稳定证据足够后再单独决策。

M4 已接受版本继续作为运行基线。docs-only 变化不触发重新部署；源代码变化仍按 M4 预览规则选择最小验证路径。

## 当前决策：本地优先、单人小步验证

当前主攻目标是：

> 让开发者本人可以反复使用 WordPress AI → Cloud → 编辑器返回 → 明确保存这条链路，并且遇到常见错误时状态可解释、不会重复写入或重复扣减。

### 完成信号

满足以下条件即可认为本阶段完成，不需要等待商业化指标：

1. 正常请求能够返回可用结果。
2. 空结果、超时、Provider 错误和格式异常不会破坏编辑器流程。
3. 保存前不写回 WordPress，只有明确保存才产生写入。
4. 对选定路径的重复点击、取消或页面重试，结果和计费状态可解释，不出现意外重复写入；两个独立新请求不能被错误当成同一次请求。复用现有 credits 幂等测试，不新增支付验收任务。
5. 开发者本人在实际需要时试用，明确反馈是否有帮助、是否需要大改、是否愿意再次使用；遇错知道下一步怎么办，由开发会话定位技术原因。

这些是待验证的完成信号，不是本次完成声明；不设必须凑齐的试用次数或日历期限。

## 下一阶段的最低成本工作方式

### 模型使用分工（操作者于 2026-09-21 明确纠正）

- AI 开发会话的自动化测试：优先使用确定性夹具、免费或本地模型，避免测试和重跑消耗正式模型费用；确需正式 Provider 集成测试时单独限定范围与预算。
- 操作者本人的真实编辑：可以接入正式模型，正常生成、修改和判断效果，不限定使用 Ollama，也不要求先完成商业化或复杂预算系统。
- AI 会话不能把个人正常使用的许可扩展为自动批量调用、合成样本、费用不受限的重试或擅自修改 Provider 配置。

操作者提供的界面截图显示 Short text、Editorial text 和 Classification 使用 DeepSeek 主模型、Ollama M4 兜底，启用兜底、重试 0 次。截图是所示配置的证据，不证明请求已经执行或实际命中了主模型。沿用操作者选择；只有结果异常或需要区分模型效果时，使用现有运行证据核对实际 Provider，不把兜底结果归因于主模型。

每次只处理一个小问题，优先使用本地数据和已有测试：

1. 先完成一条个人最常用的 happy path。
2. 每次改动只补最有价值的失败场景：超时、空结果、格式异常、重复请求或保存边界。
3. 自动化测试优先本地 Ollama、免费额度或夹具；个人真实使用按操作者配置使用正式模型。不为制造样本而调用付费模型。
4. 运行覆盖当前改动的最窄测试和合同检查，不重复执行无关的全量门禁。
5. 每隔一段时间记录一次“我实际使用了什么、哪里卡住、是否值得继续”的短结论。

### 第一步：只试标题生成

复用[已有标题试用方法](title-quality-observation-2026-09.md)，本阶段不要求完成其中的 5–10 个场景数量目标，也不新增遥测、报表或后台定时任务。

1. 选一篇现在确实需要处理的本地文章；若验证保存行为，使用可删除的草稿。
2. 使用操作者已选择的 Provider/model，可直接使用正式模型；不要求改为 Ollama。开发会话不擅自更改主模型、兜底或重试策略。
3. 正常生成一次标题，自己阅读后决定采用、小改或放弃。为了指标而反复生成没有意义。
4. 按真实需要明确保存。生成、选中和插入编辑器都不等于数据库已经保存；保留 WordPress 最终写入权。
5. 用一句话记录结果，例如：“完成了；标题相关但需小改；愿意再用。”若失败，只记卡在哪一步及无内容的错误类别。

最小记录模板如下，当前为空，不预填成功：

| 日期 / 场景编号 | 完成情况 | 是否有帮助 / 修改量 | 采用与保存 | 是否愿意再用 / 卡点 |
| --- | --- | --- | --- | --- |
| 待实际使用后填写 | 未验证 | 未评审 | 未操作 | 未判断 |

原文、生成标题、prompt、Provider payload、URL、用户身份和凭据不入仓。保存关联缺失不能推断为放弃；未计时不估算节省时间。

出现具体问题后只修复一个所属模块，并运行覆盖它的窄检查。空结果、超时和重复请求等失败分支优先复用确定性夹具，不为了制造错误而反复调用模型。没有缺陷证据时不增加代码或重复全量验证。安全、隐私或非预期写入问题立即停止该流程。

## 明确暂缓事项

以下事项本阶段不启动；将来出现需求也必须满足对应条件和授权，不能自动启动：

- 真实支付宝收款、生产支付配置和退款操作；
- 微信支付开发；
- 50 个自然样本、多人试点和完整七天商业观察；
- 为自动化测试或凑样本发起无必要的付费 Provider 调用，以及复杂的供应商账户预算系统；操作者正常使用正式模型不属于暂缓事项，现有成本与安全门槛不移除；
- 修改 GitHub branch protection；
- 生产发布和生产数据库操作。

## 重新扩大范围的触发条件

以下事实可以触发重新评估，不要求按完整商业化清单推进：

- 有一位外部试用者愿意正常使用；
- 有真实客户需要购买套餐或充值 credits；
- 出现超出个人正常使用范围的 Provider 自动化集成测试需求；
- 个人使用暴露出可复现问题时，仍先留在本阶段做有界修复。

有外部试用者再讨论受控试用；AI 会话准备执行付费 Provider 自动化实验前先明确调用/重试/金额预算和停止线，不把该实验流程强加给操作者正常编辑；准备向客户收费前再做支付宝沙箱；生产仍需独立明确授权。长期观察门槛被延后，不被取消，也不成为个人本地试用的前置条件。
