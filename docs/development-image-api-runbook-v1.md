# 开发生图 API 配置手册

Status: active operator runbook。2026-10-28 操作者确认以下模型仅用于本地/M4 开发：免费 Kolors 做测试，Z-Image-Turbo 做实际出图。生产模型由操作者上线时另行指定；本手册不指定、不自动继承生产模型，生产配置与发布仍需单独授权。

## 开发模型分工与生产边界

| 场景 | 开发模型 | 使用规则 |
| --- | --- | --- |
| 接口联调、流程测试、图片下载验证 | `Kwai-Kolors/Kolors` | 免费测试；当前 `wp-ai.image-generation` 默认保持该模型 |
| 开发阶段真正需要的配图 | `Tongyi-MAI/Z-Image-Turbo` | 操作者明确需要实际图片时使用；查询时单价 ¥0.10/张，每次一张 |
| 正式生产 | 待操作者指定 | 不把开发模型、密钥、预算或用途绑定自动复制到生产 |

这里“实际出图”仍指开发环境中的真实使用，不等于生产部署。测试失败时不得自动回退到付费模型；Z-Image 的模拟测试通过也不代表已真实调用成功。日常配置与诊断通过 SSH 完成，无需 Draw Things 图形界面。

2026-10-28 只读核对：M4 开发环境已有启用且保存密钥的 `siliconflow` 连接；官方账户目录返回 Z-Image-Turbo。原已选模型和 WordPress 生图用途为免费 `Kwai-Kolors/Kolors`。Z-Image-Turbo 当时没有当前能力验证证据，所以“账户有模型”不等于已能执行；不伪造 `verified` 状态，也不删除仍可使用的 Kolors。

## 开发配置与预算

1. 在开发后台的“AI 资源 → 硅基流动 → 模型管理”读取账户目录，选择 Z-Image-Turbo，保存。已有密钥无需重新填入，开发机文档和聊天不保存密钥。
2. 开发调用一次只生成一张；耗时上限使用现有生图用途的 90 秒，关闭自动回退和重试，避免失败后意外转向其他付费模型。
3. 使用现有 Provider 预算功能，为开发 `siliconflow` 连接配置日上限 **0.50 USD**、月上限 **2.50 USD**、80% 预警。人民币 20 元是试用预算建议，不是固定汇率或供应商余额承诺。
4. 保留其他 Provider 的现有预算策略。该开发环境原本没有启用预算设置；只对硅基流动设置预算时，`require_provider_configuration: false`，避免无关 Provider 因缺少新预算条目而被阻断。预算以 Provider 为范围，会覆盖该连接下所有实际调用，不是仅对某个模型单独计数。
5. 供应商未返回可核算费用时，现有预算按每次 **0.05 USD** 保守预留，未知费用不当作零。该规则也可能占用免费 Kolors 调用的内部预算额度，内部预留不代表供应商实际收费；遇到这种限制先核对预算记录，不自动换用付费模型。可能在供应商实际花完人民币 20 元之前停止调用；不宣称这是供应商账单、精确人民币上限或固定可生成张数。预算窗口使用 UTC 日/月。

官方价格在 2026-10-28 查询时为 Z-Image-Turbo **¥0.10/张**，约 200 张是按当时单价计算的预算示例，实际计费、活动和限流以账户为准。参考：[官方价格](https://www.siliconflow.cn/pricing)、[生图接口](https://docs.siliconflow.com/cn/api-reference/images/images-generations)。

开发与生产保持相同供应商协议、平台请求和产物合同；正式生产独立配置密钥与预算，开发密钥不自动复制到生产。当前保存的密钥是否与生产共用尚未核实，需要操作者在供应商控制台确认其用途。不要为了分离密钥新建第二套推理服务。

## 参数转换

Z-Image-Turbo 的官方接口使用 `image_size`。平台的宽高比、清晰度和数量先在适配器转换，不直接把 OpenAI 的 `size`、`n`、`response_format` 等参数发给它。

- 默认/低清方图：512×512。
- 中清：最长边 1024；例如 16:9 → 1024×576，3:4 → 768×1024。
- 高清：最长边 1536；首次开发先使用低清。
- 参数按 8 像素对齐；供应商要求或支持范围变化时只修改适配器，不改变 WordPress 请求合同。
- 模型每次只请求一张；不支持的数量在出网前明确报错。
- 不强制 `response_format`，按官方 `images[].url` 返回处理，并继续限制允许的图片下载域名。

不通过低分辨率推导供应商一定收费更低；这里的小图主要便于快速查看与流程调试。

## 首次实际使用与验收

配置、读取目录和模拟响应测试不消耗生图费用。仓库禁止付费调用仅用于制造观测数据，因此首次实际调用使用操作者真正需要的主题/提示词；不为得到“绿色结果”额外生成测试图。

免费联调保持 Kolors 为第一已选模型，并在执行后台“生图验证”前确认实际目标仍是 Kolors；该验证会调用第一可用已选生图模型，不能在 Z-Image 排第一时把它当成免费测试。读取账户目录不等同于生图验证。

当操作者需要 Z-Image 实际配图时，先确认开发账户余额、价格与预算；用该实际用途完成首次生成，图片可解码并可取回后记录真实能力证据。随后通过“运行时用途”把开发 `wp-ai.image-generation` 的首选改为该模型，保持无回退、无重试；切换前另存原 binding。完成该批实际出图后恢复 Kolors 开发默认。没有真实能力证据时，不手工伪造 `verified` 或宣称已经可路由。生产模型仍由操作者另行指定。

验收依次区分：账户目录有模型、已保存启用、当前能力证据、用途选择、Cloud run 成功、图片回读、WordPress 人工采用。只有实际发生的状态才能记为通过。

## WordPress 本地使用入口

免费手动提示词路径：媒体 → 生成图片 → 输入提示词 → Generate → 预览 → Save to Media Library；随后在文章编辑器中选择该图片，显式保存草稿。生成预览本身不应创建附件或修改文章。

编辑器的“生成特色图片”会先执行 `ai/image-prompt-generation`，再执行生图与导入。这一步文字模型单独计费，Kolors 免费不代表整个快捷流程免费；使用前核对 `wp-ai.short-text`。本次该用途指向付费文字模型，因此免费验证采用浏览器固定提示词替身，生图和导入仍实际执行；不改共享文字用途，也不据此宣称提示词模型实测通过。

当前开发站没有可用视觉模型，自动 ALT 生成会失败，官方插件仍可用原提示词作为 ALT 完成导入。可在 WordPress 媒体详情中人工编辑 ALT；不要为生图联调自动启用或调用付费视觉模型。没有验证图片编辑/参考图、批量生成或自然用户采用。
