状态：基线已整理，新增自然使用样本待积累。日期：2026-09-09。
本文件是有界阶段记录，不新增架构规范或遥测合同。

## 目标和边界

沿已有标题生成入口，判断建议是否准确、是否抓住文章重点、是否需要大改，
并核对生成、人工采用、草稿保存和反馈能否关联。只覆盖标题任务；不以此宣称
所有 WordPress AI 功能、所有站点或生产环境均已通过。

Cloud 提供运行和受控背景证据；人工阅读和质量判断在本地进行，WordPress
保留采用、保存、审批和发布权。遵循
[当前流程](current-wordpress-ai-entry-to-feedback-flow-v1.md)、
[观测授权与数据边界](production-observability-consent-and-site-support-standard-v1.md)、
[质量反馈门](cloud-agent-feedback-quality-gate-v1.md) 和
[背景证据合同](generation-context-evidence-v1.md)。

当前开发候选仅整理已有记录；预算为 45 分钟内完成文档候选、零新增 Provider
调用、零构建和零 M4 操作。后续利用正常编辑产生的样本，不为凑数生成标题、
重放事件或修改文章；不增加后台采集器、定时监控或新反馈字段。

## 第一篇文章：最短试用步骤

1. 选一篇现在确实需要编辑的文章，使用原来的 Edge 窗口。先做标题；若实际需求是摘要或改写，单独标记功能，不能混入标题样本。
2. 正常生成并阅读建议，由你决定采用、修改或放弃，再按实际需要保存。遇错只记录“卡在哪一步、界面怎么说”，实现者负责查技术证据。
3. 反馈四件事：有没有完成、结果有没有帮助、人工还改了多少、下次愿不愿继续用。
4. 记录实际开始到完成的总耗时和人工修改耗时；没有计时就写未测量，不凭感觉填秒数。若有同类纯人工任务的实际耗时，可作参考；没有可比基线就不计算节省比例。

文章地址、原文和生成内容留在本地，不填入下面的入仓表。当前新增试用仍为零，
待操作者提供文章和亲自判断。开发者自己的试用只能证明自身收益；非开发者目标用户
的价值需另行参与和反馈，不能由本次内部试用替代。

## 正常使用时如何记录

首批目标为 5–10 个不同文章场景，用于发现问题，不用于估计稳定采用率。
按实际遇到的顺序纳入成功、失败和未采用情况，避免只选择满意结果；同一文章
多次生成属于一个场景内的多次尝试，不能作为多个独立文章样本。
一个站点的结果不能代表跨站点质量。

1. 正常需要改标题时，由操作者使用现有入口；保持现有采集同意和数据策略。
2. 操作者在本地对照文章与建议，记录下表的人工判断。没有人工阅读就填未评审。
3. 按操作者真实需要决定采用与保存。没有动作或缺少遥测均不能推断为拒绝。
4. 用现有日志、运行结果和本地保存证据关联同一运行；需要时复用 Addon 已有
   `composer run local:journey:inspect` 只读工具，不手工 flush 或重放。
5. 在本记录中追加无内容摘要。原文、生成标题、prompt、Provider payload、
   客户 URL、用户身份及凭据不入仓；原始材料留在已有授权的本地路径。

| 记录项 | 填写规则 |
| --- | --- |
| 样本编号、日期、场景 | 使用 T01 起的编号和不含客户内容的场景类别 |
| 环境和版本 | 写明实际观察环境、已知插件/源码版本；未知明确标记，不能用 master 代替部署版本 |
| 运行关联 | 仅在既有数据规则允许时保留 run 引用；否则注明受控证据位置，不新增身份字段 |
| 人工准确性 | 准确／不准确／无法判断；不准确时记录无内容的原因类别 |
| 人工重点覆盖 | 符合／偏离／无法判断 |
| 人工修改量 | 无需修改／小改／大改／未评审；原样保存本身不代替人工评分 |
| 实际耗时 | 总耗时、人工修改耗时；未计时记未测量，同类纯人工基线需说明来源与可比限制 |
| 主观收益与继续使用 | 有帮助／无帮助／无法判断；愿意继续／不愿意／待定，记录简短原因 |
| 参与者类别 | 开发者本人／非开发者目标用户；不记录个人身份 |
| 实际采用与保存 | 未操作／明确未采用／已插入未保存／原样保存已确认／修改后采用已确认／无法确认 |
| 背景证据 | 按原结果记录 applied、unavailable、not_requested；字段缺失记未记录，保留期限或 no_store 导致不可读记不可获得 |
| 反馈关联 | 已匹配／待自然上传／无法确认；以同站点同运行证据为准 |
| 问题和证据 | 简述入口、连接、运行、背景、建议质量、保存或反馈问题；无证据不归因 |

`saved_after_generation_unmatched` 只说明生成后保存且未精确匹配，不能自动记为
“修改后采用”。背景字段缺失不能记为背景未应用；`no_store` 及过期结果不为观察
目的重新获取内容或重跑模型。这里只维护人工记录，不修改事件枚举或 API。

新增自然样本：0。新增人工评审：0。当前质量结论：尚不足以判断。

## 何时改代码，何时继续观察

出现可复现的连接、日志关联、保存或反馈错误时，先定位到具体 owner；存在数据
泄露、错误写入等严重问题时立即停止受影响操作，不等样本凑齐。只把一个有证据
的问题纳入修复，按其实际风险选择测试和候选运行门。

若问题仅表现为标题质量，先人工复核原文与建议。背景已应用不构成收益证明，
一次不满意不直接触发模型切换或检索重构。至少说明受影响场景、判断依据与
可观察改善，再确定是否需要修改。未找到明确问题则继续正常使用，不做结构整改。

修复前保留相关失败用例或无敏感信息的合成用例；修复后用相同评价规则比较。
确定性夹具证明软件行为，人工评审证明所评样本的质量，两者分别报告。需要额外
付费对比调用时另行界定具体样本与预算；本文不安排批量模型实验。

首批达到 5 个已评审场景时进行一次小结；存在有价值的场景缺口时可扩至 10 个。
不因等待正常使用而无限延长活跃开发任务，也不默认安排自动唤醒。出现第二个独立
阻塞后停止扩展修复范围，列入后续。统计只报告已评审数量、问题类别与证据限制，
不把小样本通过率、采用动作或缺失事件当作普遍质量结论。
