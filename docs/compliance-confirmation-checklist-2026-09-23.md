## 1. 方向一：生成式 AI 服务监管适用边界

| 问题 | 初步理解（附来源） | 需操作者确认的点 | 对产品的影响面 |
| --- | --- | --- | --- |
| ☐ 1.1 "面向站长提供 AI 内容提效云服务"是否落入《生成式人工智能服务管理暂行办法》（2023-08-15 施行）的"向境内公众提供生成式 AI 服务"？ | 办法第 2 条：利用生成式 AI 技术向境内公众提供生成文本等内容的服务适用；行业组织、企业等"研发、应用生成式人工智能技术，未向境内公众提供……不适用"。律所实务解读多以"是否公开注册、面向不特定用户"作为"公众"的判断线索。当前仅操作者本人试用、未公开注册，形式上接近"未向境内公众提供"；对外公开注册售卖时落入风险显著上升。来源：网信办办法原文；竞天公诚等解读（第 6 节 S14）。 | 公开售卖前的服务形态（公开注册 / 定向邀请 / 白名单）；站长群体是否被视为"公众"；是否用邀请制延缓适用时点。 | Portal 公开注册入口的开启时点；cloud-addon `npcink-cloud` 连接器的 `title_generation`/`content_summary` 生成链路。 |
| ☐ 1.2 若落入，走"大模型备案"还是"调用已备案模型的应用登记"路径？ | 办法第 17 条：具有舆论属性或者社会动员能力的服务应开展安全评估并履行算法备案。网信办 2026 年公告口径：自研大模型向公众提供需国家网信办备案；"通过 API 接口或其他方式直接调用已备案模型能力的生成式人工智能应用或功能"由地方网信部门登记。我们不训练基础模型，若落入更可能走"登记"路径。来源：办法第 17 条原文；网信办已备案信息公告（S5）。 | 写作提效工具是否被认定"具有舆论属性或社会动员能力"（生成内容会被站长公开发布，建议从严评估）；登记材料与属地网信部门口径；办理周期对上线排期的影响。 | runtime 域 provider 执行链路；公开注册排期依赖此项。 |
| ☐ 1.3 所调用的模型是否都具备"已备案"前提？ | "登记"路径以底层模型已备案为前提；网信办定期公告已备案名单。境内主流模型多已列入；境外模型未在境内备案，若用于面向境内公众的服务，登记路径存在障碍。来源：网信办已备案信息公告（S5）。 | 逐个核对所用 provider / 模型是否在公告名单内；境外 provider 是否保留在面向境内公众的服务组合中，还是仅限 BYOK 自担场景。 | provider 连接配置与路由 profile；混合 BYOK 模式（strategy 第 7 节）下用户自带 key 调用境外模型的责任划分。 |
| ☐ 1.4 除网信部门要求外，还触及其他行政许可吗？ | 办法第 23 条：法律、行政法规规定提供生成式 AI 服务应取得行政许可的，应依法取得。对收费云服务最直接的候选是增值电信业务经营许可（ICP 证），见方向三。来源：办法第 23 条原文。 | 与 3.1 合并确认。 | 商业化 closeout 门槛（strategy 第 9 节境内就绪度）。 |

## 2. 方向二：AI 生成合成内容标识义务

《人工智能生成合成内容标识办法》（四部门 2025-03-14 发布，
2025-09-01 施行）与配套强制性国标 GB 45438-2025《网络安全技术
人工智能生成合成内容标识方法》（同日施行）。

| 问题 | 初步理解（附来源） | 需操作者确认的点 | 对产品的影响面 |
| --- | --- | --- | --- |
| ☐ 2.1 我们是否属于本办法的"服务提供者"？ | 办法第 2 条：适用于符合《互联网信息服务算法推荐管理规定》《互联网信息服务深度合成管理规定》规定情形的网络信息服务提供者；适用前提与方向一同源（是否面向境内公众提供服务）。来源：标识办法原文（S2）。 | 与 1.1 同一判断、一并下结论；若不落入，记录判断依据备查。 | 生成产物 API 返回结构；cloud-addon 展示层。 |
| ☐ 2.2 若适用，显式标识加在链路哪个环节？ | 办法第 4 条按深度合成规定第 17 条第 1 款情形要求显式标识（文本类为"起始、末尾或者中间适当位置添加文字提示或者通用符号提示"）。我们的生成结果先进入站长编辑器而非直接公开展示，显式标识的落点（API 返回即带提示 / 插件界面展示 / 站长发布时声明）需按 GB 45438-2025 与网安标委实践指南确认。来源：办法第 4 条；S3、S4。 | 文本类结果返回站长时是否需带显式提示；站长实质性编辑后标识是否保留、何时可视为已转化。 | `title_generation`/`content_summary` 返回体；cloud-addon 连接器 UI；artifact 下载 / 导出。 |
| ☐ 2.3 隐式标识（元数据）三要素如何在链路中携带？ | 办法第 5 条：在文件元数据中添加隐式标识，包含生成合成内容属性信息、服务提供者名称或编码、内容编号等制作要素，鼓励数字水印。纯文本建议类产物没有"文件"载体，元数据落点需按国标确认（如 API 响应字段）。来源：办法第 5 条；S3、S4。 | 文本产物的元数据承载方式；Cloud 留存的 artifact / 运行记录是否需同步保留内容编号。 | runtime 生成产物与 artifacts 域；observability 记录字段。 |
| ☐ 2.4 站长一侧承担什么，产品如何支持而不越界？ | 办法第 10 条：用户发布生成合成内容时应主动声明并使用服务提供者提供的标识功能；任何组织和个人不得恶意删除、篡改、伪造、隐匿标识，**不得为他人实施此类行为提供工具或服务**。站长是"用户/发布者"；第 6 条传播平台核验义务主要指向提供内容分发服务的平台，站长个人网站一般不构成。来源：办法第 6、10 条原文。 | 是否为站长提供"主动声明 / 一键标识"便利功能；含 UGC（评论）的站长站点是否构成传播平台（属站长义务，但影响我们给站长的指引文案）。 | cloud-addon 站长侧 UI 与使用说明；产品任何位置不得出现"清除 AI 标识 / 剥离元数据"类功能（第 10 条禁止提供此类工具）。 |
| ☐ 2.5 已施行的办法是否存在需要先自查的存量义务？ | 办法 2025-09-01 已施行；当前服务未公开注册、生成内容仅存在于操作者本地试用链路，尚无面向公众的存量传播。来源：办法第 14 条。 | 公开注册前是否一次性盘点历史生成产物与本地试用记录。 | 无即时代码影响；公开注册开关前的 checklist 项。 |

## 3. 方向三：收款与经营合规

| 问题 | 初步理解（附来源） | 需操作者确认的点 | 对产品的影响面 |
| --- | --- | --- | --- |
| ☐ 3.1 收费云服务需要 ICP 许可证，还是 ICP 备案即可？ | 《互联网信息服务管理办法》（国务院令第 292 号，2011 修订）第 3 条：经营性互联网信息服务指"通过互联网向上网用户有偿提供信息或者网页制作等服务活动"；第 4 条：经营性实行许可制度、非经营性实行备案制度。cloud.npc.ink 已实测收费且目前仅完成 ICP 备案——若被认定为经营性，需取得增值电信业务经营许可证（ICP 证）。来源：办法第 3 条原文（S6）；云厂商备案指引（S15）。 | "AI 提效工具订阅 / 额度收费"是否被认定为经营性；省通信管理局口径。**全部问题中优先级最高**（见第 5 节）。 | 商业化正式售卖的总开关；strategy 第 9 节境内就绪度。 |
| ☐ 3.2 个体工商户主体能否承接所需资质？ | 《电信业务经营许可管理办法》要求增值电信业务经营者为依法设立的公司（省内经营注册资本最低 100 万元），个体工商户不能申请 ICP 证。若 3.1 结论为需要 ICP 证，收款主体需升级为公司。来源：《电信业务经营许可管理办法》（S8）；实务指引（S15）。 | 是否及何时设立公司；个体工商户阶段是否保持"不对外公开售卖"。 | 主体变更牵连收款账户、合同主体、备案主体与支付宝商户主体。 |
| ☐ 3.3 网络交易经营者的公示义务是否满足？ | 《网络交易监督管理办法》（2021-05-01 施行）要求网络交易经营者公示营业执照等信息（亮照），自行终止经营提前 30 日公示；《电子商务法》将通过网络提供服务的经营者纳入调整。来源：办法原文（S9）。 | 服务页 / Portal 页脚是否公示主体信息与 ICP 备案号；用户协议、价格与退款政策是否随售卖页一并提供。 | `site/` 静态服务页与 Portal 页面；售卖 closeout 前置项。 |
| ☐ 3.4 发票与退款政策如何落地？ | 《发票管理办法》（2023 修订）：提供服务收取款项应向付款方开具发票，付款方索要不得拒绝；个体工商户可领用或申请代开。退款：服务类以约定为主（七日无理由退货主要适用网购商品），退款政策需公示；产品侧退款能力缺口已有静态盘点。来源：发票管理办法（S12）；[refund-gap-inventory-2026-09-22.md](refund-gap-inventory-2026-09-22.md)。 | 开票流程（电子普通发票）与索取入口；退款政策条款文本与产品退款流程对齐（退款能力本身见盘点文档）。 | 商业域支付 / 退款流程；服务条款页。 |
| ☐ 3.5 若提供订阅自动续费，提醒义务如何实现？ | 《消费者权益保护法实施条例》（2024-07-01 施行）：经营者采取自动展期、自动续费方式提供服务的，应在消费者接受服务前和自动展期、续费日期前以显著方式提请注意。来源：实施条例及解读（S11）。 | 商业形态是充值 / 额度还是订阅；若含自动续费，提醒通知的产品实现。 | 商业域订阅功能设计（未实现前无影响）。 |

## 4. 方向四：数据合规

| 问题 | 初步理解（附来源） | 需操作者确认的点 | 对产品的影响面 |
| --- | --- | --- | --- |
| ☐ 4.1 站点内容上云的个人信息处理关系如何定性？ | 站点是个人信息处理者（站点内容可含评论者昵称、邮箱等），Cloud 接受站点委托做索引 / 检索，构成《个人信息保护法》（2021-11-01 施行）第 21 条的受托处理：应约定处理目的、期限、方式、个人信息的种类、保护措施及双方权利义务，并接受监督。来源：个保法第 21 条原文（S13）。 | 服务协议中是否已有要素齐全的数据处理（委托处理）条款；站点内容同步范围是否可配置排除个人信息密集内容。 | site_knowledge 同步与 embedding 链路；cloud-addon 授权与协议文案。 |
| ☐ 4.2 留存期限如何确定？ | 个保法第 19 条：个人信息保存期限为实现处理目的所必要的最短时间。财务凭证按会计档案管理要求保存；《电子商务法》第 31 条要求数字平台类交易信息保存不少于三年（我们为自营服务而非平台，是否类推适用以确认结论为准）。来源：个保法第 19 条（S13）；电子商务法第 31 条（S10）。 | chunks / 向量、运行日志、artifacts 各自的留存期限与清理机制（对照现有 retention / cleanup 能力）；财务凭证保存年限。 | site_knowledge retention 与 ops 清理任务；artifacts 清理。 |
| ☐ 4.3 境内存储与数据出境？ | 服务器位于境内、服务对象为境内站长，常规链路不涉及出境；若经境外 provider 传输站点上下文（可能含个人信息），可能构成数据出境，需按数据出境相关规定评估路径（豁免情形 / 标准合同等）。来源：境内就绪度事实（S1 内部记录）；数据跨境流动现行规定（公开检索线索，未核验原文，待补）。 | 是否在面向境内站长的链路中使用境外 provider；若用，出境合规路径与告知同意义务落点；BYOK 场景下站长自带 key 直连境外 provider 的责任划分。 | provider 路由与 outbound endpoint policy；混合 BYOK 设计。 |
| ☐ 4.4 等级保护与数据安全基础义务何时办理？ | 《网络安全法》确立网络安全等级保护制度，网络运营者需定级、备案、按级测评；《数据安全法》要求数据分类分级管理。实践中工具类云服务常见定级为二级。来源：网络安全法、数据安全法（公开原文，通用义务，未逐条核验）。 | 等保定级备案的办理时点（公开售卖前 / 后）与办理主体；分类分级的最小可行落地方式。 | 运维 closeout 清单；不直接触发代码。 |

## 5. 最需要先确认的三件事

1. **3.1 + 3.2（ICP 许可与主体资格）**：收费是否被认定为经营性互联网信息
   服务、个体工商户不能持有 ICP 证——这两项共同决定商业化的主体路径与
   排期，是其余一切收款侧动作的前提。
2. **1.1 + 1.2（生成式 AI 服务适用与备案 / 登记路径）**：对外公开注册的
   时点即适用时点；登记路径与材料决定公开售卖的前置周期。
3. **4.1（数据处理委托条款）**：site_knowledge 同步链路已在运行，服务
   协议中的委托处理条款是这条链路需要的协议基础，宜在引入外部站长前
   完成。
