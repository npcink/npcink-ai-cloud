# Admin 信息层级与版式逐页审查 — 2026-10-29

状态：只读巡查完成；下列内容是改造建议，尚未实施 UI，也不是界面验收记录。

## 结论与范围

优先改进的是「判断事实的可见性」，随后才是减少文字和卡片。当前后台已有
不少正确模式：供应商目录、覆盖队列、运行诊断的工作面较清楚；通用说明也
已有帮助和折叠入口。但局部页面把动态结论当说明隐藏，把分布图、重复摘要、
技术标识或整列强调按钮放在更高位置，造成重要程度与视觉重量不一致。

本次聚焦 Admin 内容优先级、动作层级、首屏工作面、布局密度和披露入口。
不改应用代码、数据口径、权限、运行路由、商业规则或暂停状态，不触发保存、
测试连接、模型调用、消息发送、发布或部署。

  `0be21119af7093975d1195f0947a4b94c167fa68`。初始已有页缓存显示过旧 revision，

## 建议先后顺序

下表优先级表示改进顺序，不是安全漏洞严重度。

| 顺序 | 改进对象 | 先解决什么 | 完成判断 |
| --- | --- | --- | --- |
| 第一批 | 首页、客户/站点详情的状态呈现 | 必要结论藏在标题帮助、无所属标签的状态、风险容器把正常值染红 | 不展开帮助就知道当前对象、异常原因、下一步 |
| 第一批 | 向量观测 | 大图与稀疏分布占上方，错误队列下沉；健康分与次数易混淆 | 异常调查工作面进入首屏；健康分与次数分别标明 |
| 第一批 | 插件观测 | 多条不同错误被泛化成相同文字，原始流水默认过长 | 可在打开详情前区分对象/问题；原始记录有界预览 |
| 第一批 | 编辑质量、Agent 反馈 | 小样本下的 100% 和「无问题」比采集阶段更醒目 | 分母、采集阶段、证据限制与指标一起可见 |
| 第一批 | 向量设置、派生媒体空态 | 配置缺口靠下；暂停功能空态仍引导产生新任务 | 配置下一步靠前；暂停与历史观察语义明确 |
| 第二批 | 用量、订阅、设置、客服 | 工具条多行、重复汇总、说明与强调按钮占用工作面 | 主工作面更早出现；高频动作仍可见 |
| 第三批 | 供应商、套餐、积分包、经济性等 | 已较清楚页面的重复文案、技术细节和局部间距 | 保留现有模型，局部收敛，无功能或口径扩张 |

按页面/模块分别交付，不做一次全站换壳。第一批涉及共享标题的调用方式，
应先修调用方：不要全局展开 `description`，也不要全站强制改 density。

## 共同根因与可复用规则

### 标题帮助不能替代状态摘要

[BackofficeScaffold](../../../../../frontend/src/components/backoffice/BackofficeScaffold.tsx)
的 `BackofficePageHeader`：default density 把 `description` 放入
`BackofficeInfoHint`，compact density 则行内显示。调用方仅看 prop 名称容易误判。
首页平台结论、客户覆盖判断等动态事实被一起藏进帮助。

稳定的页面职责、名词定义留在帮助；当前结论、阻塞和下一步进入现有摘要/状态
区域。不要为补回一个动态结论而把所有说明同时展开。

### 降低描述权重，不降低判断能力

建议四类盘点：常显、按需、技术证据、删除重复。适合 hover/focus 的是一两句
术语或口径；长段规则用明确命名的折叠区；原始错误、完整 ID、流水进对象详情。
重复句直接删，不再装进另一个「更多」区。

对象身份、当前范围、错误/阻塞原因、关键单位、样本不足、截断/过期、未保存
或失败反馈必须常显。没有这些事实，页面虽然更空，却更容易误判。高频行操作
保留可见，用中性样式减重；不改成 hover-only。

### 工作面与动作先于说明和分布

首屏先出现当前任务对象和工作面开头。异常页先异常及调查入口；配置页先生效
状态和缺口；详情页先对象和当前处境。必要趋势保留，补充分布按需。大数字、
绿色就绪标签、整列蓝按钮、重复卡片并不天然更重要。

不为填满空白制造卡片；短表单保持阅读宽度，宽表利用工作区。控件按同一任务
组合，减少刷新、视图、维度分别占一整行。正常状态保持安静，异常有明确归属。

## 后续实施的交付门槛

每一批先写操作者任务和四类清单，明确每项被移走内容的目的地。沿用
[Quiet 路由契约](../../../../admin-ui-spec.md)、
[状态所有权规范](../../../../admin-disclosure-state-ownership-standard-v1.md) 和
[PC 选择性验证规则](../../../../frontend-pc-scope-and-selective-verification-v1.md)。

UI 实施前后用同页面、同范围、同状态的截图比较：首屏是否出现工作面、对象是否
可区分、核心限制是否仍看得到、高频动作是否可达。影响交互时再验证展开/收起、
键盘 focus、返回上下文、失败和部分数据状态。共享 primitive 改动按 shared 风险
补相应路由验证，不能把局部截图当成全站通过。

不使用以下验收捷径：只看 type-check、把所有段落移进「更多」、降低文字对比度、
隐藏行操作、更新 golden 掩盖变化、报告未经测量的节省百分比。

本次固化的是规范和 PR 评审入口，并未新增自动视觉判断器。后续 AI 的静态检查
通过仍须接受浏览器证据审查。
