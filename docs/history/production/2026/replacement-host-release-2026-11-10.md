## 上次失败与本次修复

上次候选 `4dd570c2` 的 API 依赖检查通过，Worker 曾写入心跳，
但运维汇总请求超过固定 5 秒预算，未通过流量恢复前的检查。
工作站经严格 SSH 隧道的只读剖析为约 16.16 秒、108 次 SQL；
该数字包含工作站路径耗时，不能当作新机原生 HTTP 基准。
回滚时先删除仍被候选容器引用的最后镜像标签，Docker 拒绝，因而保留锁。
没有证据证明当时 Worker 崩溃或 OOM。

#1392 将复杂运维投影请求预算改为默认 30 秒、可配置 1–60 秒，
便宜依赖检查仍为 5 秒；新心跳、精确容器、稳定窗口及严格就绪判定保持。
无前序发布时先移除候选容器，再恢复镜像标签原有缺失状态，保留卷。
本次不是查询优化，跨地域数据库往返仍是后续性能改进点。

操作者明确授权后，恢复程序先核对原 marker、manifest、锁、唯一残留
Redis 身份、原配置及备份，再保存原始证据，仅移除匹配残留容器，
恢复原有标签缺失状态，最后释放失败锁。恢复完成不冒充上线成功。
新的受保护回执随后绑定最终 production 源码、manifest 和真实新备份时间。
详见[替换主机恢复契约](../../../replacement-host-recovery-v1.md)。
