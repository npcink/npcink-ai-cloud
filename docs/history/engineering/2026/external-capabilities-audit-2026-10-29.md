## E01 · P1 · 读取失败仍显示确定的“停用 / 未配置”，并允许写入

**范围：当前 M4 构建、隔离 GET 503 复现。** 搜索与图片初次请求失败后仍显示 `0/10`，全部服务“停用 / 未配置”，配置按钮可用。向量请求失败后显示“未配置”、0 篇资料、需要重建，并允许填写和保存。虽然有加载失败通知，主体仍提供了不成立的配置事实。

原因：`frontend/src/app/admin/external-services/page.tsx:117` 失败后保留初始化空数组；向量页 `frontend/src/app/admin/vector-settings/page.tsx:132` 失败后保留 null，随后以可写的默认未配置视图渲染。

**建议：** 区分未加载、加载失败、成功空配置和同范围旧快照。首次失败只提供重试，禁止根据未知连接选择 POST/PATCH；旧快照刷新失败时标注快照陈旧，并限制依赖最新配置的写操作。

**验收：** 首次 503 不出现确定的 0、停用或未配置结论；不能从未知状态提交配置；重试成功后恢复正常目录，不能覆盖已有配置。

## E02 · P2 · 搜索与图片忽略已有连接验证失败，仍显示“已就绪”

**范围：M4 真实未验证元数据、隔离失败连接复现。** 将已配置并启用的 Pexels 连接设为 `verification_status=failed`、错误状态及验证失败关注原因，列表仍显示“已就绪 / 已保存 / 实际运行：并行来源”。真实响应中两家图库的 `not_observed` 也未展示。

原因：该页 `:139` 和 `:306` 仅由 enabled 与 configured/secretless 推导 ready，不消费 verification、attention 和最后错误。测试失败的临时行提示刷新后也会消失。

**建议：** 分开显示“配置已保存”“运行调用启用”和“连接验证通过 / 未验证 / 失败”。不因未验证自动停用既有服务，但应持久显示已知失败及重试入口，摘要口径与列表一致。

**验收：** 启用且已配置的失败连接不能显示为验证通过；刷新后失败证据仍在；未验证不冒充失败或通过，现有运行选择不被擅自改变。

## E03 · P1 · 保存成功但回读失败后，旧状态仍可冒充当前状态

**范围：当前构建、隔离 PATCH 成功 + 后续 GET 503 复现。** 将 Doubao Search 的运行开关从启用改为停用，拦截 PATCH 返回成功，使回读失败：编辑器关闭，行提示“外部服务设置已保存”，列表却仍为“启用 / 当前生效”。输入被清空，用户无法从列表确认实际写入结果。

原因：搜索页 `:117` 的加载函数捕获错误但不返回失败；`:211` 保存流程等待后仍无条件关闭编辑器，并继续使用旧 connections。

**建议：** 将写入回执与回读结果分开。明确提示“已保存，最新状态读取失败”，保留对象上下文；重试只读取，不重复保存。可先用服务端写回响应更新连接，再以回读确认跨连接变化；禁止把未确认旧行显示为当前事实。

**验收：** PATCH 成功、GET 失败仅产生一次写请求；用户看到明确部分成功回执；再次操作不会基于旧状态误切换或重复创建。

## E04 · P1 · 自动刷新覆盖 Endpoint 草稿，并保留与之不匹配的新 Token

**范围：当前构建、隔离 rebuilding 状态和真实 15 秒定时器复现。** 服务端 Endpoint 为 `https://saved.audit.invalid`，输入草稿 `https://draft.audit.invalid` 与假 Token。下一次轮询后 Endpoint 自动变回 saved，Token 草稿仍保留。该组合继续保存可能把新 Token 配到旧 Endpoint。

原因：向量页 `:132` 每次 loadProfile 都重设 Endpoint 和凭据替换显示状态；`:163` 在 rebuilding 时轮询，未区分服务端快照与编辑草稿。

**建议：** 独立保存草稿及 dirty 标识；后台只刷新验证快照。Endpoint/Token 作为同组草稿处理；草稿与新服务端配置冲突时明确提示，不静默替换。

**验收：** 重建期间至少两次轮询不改变用户输入；新 Token 不会被配到旧 Endpoint；取消编辑后才恢复已保存值。

## E05 · P1 · 保存期间仍可编辑且可并发重建，随后清空新输入

**范围：当前构建、隔离延迟 PUT 复现。** 保存假密钥 A 后暂缓响应，密钥框仍可编辑为 B；“重建向量索引”也可点击。拦截到的顺序为 Embedding PUT、index-rebuilds POST、vector-store PUT。释放响应后，实际提交的是 A，新输入 B 被清空，页面却显示配置已完成。

原因：`:171` / `:188` 使用提交时闭包并在成功后无条件清空输入；`:779` 保存按钮只关注保存状态，`:951` 重建按钮只关注 rebuilding；输入没有相同的操作锁。

**建议：** 统一保存与重建的互斥状态，重建要求连接就绪。提交使用固定草稿版本；可以在提交期间锁定相关输入，也可以保留后续版本，但成功响应只能清除已提交版本。

**验收：** 保存与重建不能重叠发出；保存中输入禁用或明确保留新版本；迟到响应不清除新草稿，失败也不丢输入。

## E06 · P2 · 等待站点同步时顶层返回 ready，页面停止自动刷新

**范围：当前 master 后端隔离复现 + 当前构建响应夹具。** 复用现有 `test_vector_rebuild_requests_automatic_site_sync_for_wrong_embedding_space`，以 Fake Provider/后端和临时 SQLite 调用当前 master 服务。两次 get_profile 均返回顶层 `status=ready`，而 `validation.index.status=awaiting_site_sync`。浏览器回放这一结果时，生产配置显示“已就绪”，索引显示“站点更新中”；观察跨过 15 秒周期，GET 数仍为 1。

原因：`app/domain/site_knowledge/vector_profile.py:122` 仅透传 reindex_required / rebuilding / failed，漏掉 awaiting_site_sync；前端 `:163` 只看顶层状态决定轮询。

**建议：** 顶层聚合状态覆盖完整的索引生命周期；前端轮询直接依据明确的进行中状态。连接就绪与索引就绪分别表达，不以连接通过结束整个同步流程。

**验收：** 请求站点自动重送后，返回 awaiting_site_sync；页面持续刷新并能观察完成/失败，不需手动刷新；终态停止轮询。

## E07 · P2 · 尚未完成连接，被误报为“需要重建”且没有对应操作

**范围：M4 实际页面与只读响应。** 当前生产连接未配置，连接检测 not_ready、索引 not_ready；页面显示“需要重建”，但没有重建按钮。Cloud 的 2132 篇资料、2364 个分块是来源计数，不能证明 Zilliz 已可重建或索引损坏。

原因：向量页 `:868` 对未明确识别的索引状态统一显示“需要重建”，而 `:489` 只对 reindex_required / awaiting_site_sync / failed 显示操作。

**建议：** 为 not_ready 显示“等待连接配置”，下一步指向连接检测；rebuilding 显示进行中，未知状态显示无法识别。重建只对适用状态开放。

**验收：** 未配置不提示重建；状态文案、前置条件与可用操作一致；来源分块与已索引分块保持区分。

## E08 · P2 · 已检索但零命中被当成“等待验证”

**范围：当前 master 状态契约、当前构建隔离响应。** 返回 `retrieval.status=no_hit`、明确检索时间和 result_count=0，页面仍显示“等待验证”，并提示再执行正常搜索，没有展示这次已完成的检索证据。

原因：向量页 `:906` 仅区分 passed / failed，其余回落 pending；后端 `_validation_state` 已能独立返回 no_hit。

**建议：** 增加“已检索，零命中”状态及时间/数量；提示检查资料、索引范围或查询相关性，避免将零命中简单判成故障或要求反复制造验证调用。

**验收：** pending / no_hit / failed / passed 分别可识别；零命中显示 0 和实际时间，不能显示尚未执行。

## E09 · P2 · 图库页签刷新后丢失，链接不能复现当前工作区

**范围：当前 M4 构建交互复现。** 切到“图库来源”时 URL 仍为 `/admin/external-services`；刷新后回到网页搜索。

原因：搜索页 `:94` 只用组件内 category 状态。

**建议：** 将服务分类写入 URL，处理未知值与前进/后退；保留当前分类的对象上下文，不把凭据草稿写入 URL。

**验收：** 图库链接可分享、刷新和返回；页面不会静默切到另一服务类型。

## E10 · P2 · 工作区声明为页签，但缺少对应键盘与面板关联

**范围：模型供应商 M4 实测、搜索页源码。** 在连接设置页签聚焦后按 ArrowRight，焦点与选中项均未移动；三个 role=tab 全部 tabIndex=0，没有 aria-controls，也没有 role=tabpanel。鼠标切换、Tab 后 Enter 仍可使用，不能描述为整个工作区不可访问。搜索/图库页签采用相同不完整模式。

原因：模型供应商页 `:1633` 起及搜索页 `:258` 只设置了 tab / aria-selected。

**建议：** 按现有后台组件约定补齐左右方向键、Home/End、单一 tab stop、tab 与 panel 关联；也可按实际交互改用普通按钮组，但不要保留不完整页签语义。

**验收：** PC 仅键盘可切换并进入对应面板；选中态与焦点可区分；Escape 与弹窗焦点行为继续通过。
