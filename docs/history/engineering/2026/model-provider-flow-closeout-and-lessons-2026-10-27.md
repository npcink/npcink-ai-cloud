### 未返回型号的根因与防线

旧预设预填硬编码型号、保存未校验账户目录、同步为避免中断而保留已配置
型号，三者组合导致“目录没返回但一直存在”。只删除一个异常型号会复发。
现有规则同时约束预设、只读参考入口、Admin 写接口和空列表语义：
`config.model_ids: []` 明确表示不启用任何型号，不能回退恢复默认值；只有
字段缺失的旧连接保留兼容。改变连接身份后不能沿用旧目录证明。
已有未返回型号可保留或移除，移除后重新启用必须重新取得账户证据。
没有账户目录、只提供部署 ID 的新接入目前不走普通 Admin 启用路径；
有实际需求再单独设计，不恢复通用任意型号写入。

## 可复用的开发经验

1. **先划清事实来源，再精简界面。** 账户可用、保存选择、参考资料、能力
   验证和实际调用是不同事实；折叠布局无法修复混用来源的根因。
2. **保存是一个明确事务。** 独立草稿、单用途 PATCH、失败保留、取消丢弃；
   技术回执可追溯，但不能与业务成功重复喊话。详见上述运行配置及反馈契约。
3. **用真实最短路径验证。** 配置成功后走调用、审阅、显式保存、用量和反馈；
   本地 Ollama 能发现兼容路由问题，无需为凑证据调用付费模型。
4. **同时检查内容和写入边界。** HTTP 200、输出格式、反馈幂等通过后，还需
   看事实、语气与不确定性；Cloud 不接管 WordPress prompt 或最终采用真相。
5. **费用未知必须可见。** 参考价不是账单，未知不是零；调用前持久预留，
   部分未定价不提前释放。见 [事务边界](../../../runtime-provider-transaction-boundary-v1.md)。
6. **按一个问题拆批。** 本批积累到 125 个文件，导航、模型、预算、基线及
   镜像维护扩大了审查面。后续按用户问题或风险拆分，保留强制门禁；外观
   仅跑受影响 PC 检查，文档不重启运行环境。
7. **收尾以可恢复为准。** 提交、CI、合并、预览接受、文档、分支和工作树
   分开核对；先保全忽略证据再退休自己的资源。清理不等于删除其他会话
   或 M4 运维工作区，历史文档也不能成为下一次删除授权。
