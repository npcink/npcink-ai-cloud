## 反复出现的产品问题与检查方法

| 模式 | 前序实例 | 可复用检查与修复原则 |
| --- | --- | --- |
| 未知被当作零或默认配置 | 运行配置四个 0、零分母覆盖率、无效媒体识别策略 | 明确区分 loading、unknown、empty、ready、stale、error；读取失败不得提供可提交的猜测默认值 |
| 快照脱离范围 | 审计/反馈切换筛选仍展示上一范围 | 为快照记录 site/window/filter/page 身份；范围变化立即隔离旧结果，同范围刷新失败才允许带陈旧标签保留 |
| 保存与回读混为一谈 | 外部能力及服务设置保存后 GET 失败 | 保存已成功、回读待确认分别表达；重试只读，不自动重复写；旧快照冻结，恢复后再允许编辑 |
| 在途输入和迟到响应竞争 | 向量后台轮询覆盖草稿、设置提交期间继续修改 | 服务端快照与草稿分开；写入期间锁相关控件；防重入、请求版本或取消机制必须与状态归属一致 |
| 状态与证据不一致 | 启用当成验证通过、选定模型当成实际调用、Apply 当成保存 | 分开配置/启用/验证/实际执行/采纳；指标可追溯分子、分母、时间、样本来源及截断上限 |
| 聚合和展示顺序错误 | 告警只按前 N 家族计算、历史先 limit 后分类 | 先筛选和聚合，再裁剪展示；精确查找不替换成其他对象；说明展示上限 |
| 导航看似切换、状态不恢复 | 同路径 URL 不更新页签、媒体识别入口不开弹窗 | 验证直接链接、同路径 query、刷新、前进/后退、显式定位缺失；页签和弹窗都验证键盘及焦点 |
| 错误提示指向错误层级 | 上游 502 被解释成迁移错误 | 保留错误层级和可执行下一步；代理故障、鉴权、契约无效、业务验证分开，不猜数据库或生产根因 |
| 语言变化触发数据副作用 | 切换语言重新读取设置并清空草稿 | 让数据读取身份独立于翻译函数；语言改变只改变呈现，除非接口本身需要语言参数 |

## 已证实有效的做法

- 先保存代码，再做下一批工作；同一任务分支保留前序变更，精确暂存，避免清理混合工作树。
- 正常、首次失败、同范围刷新失败、跨范围失败、保存后回读失败分别检查，能发现只跑成功路径遗漏的问题。
- 用本地隔离响应验证写操作与异常，再用 M4 只读核对真实路由/接口/候选身份；不为观测制造付费调用。
- 页面定向检查与共享门禁按影响选择；PC 1440px 与 900px 检查操作可达，主题按影响补查；重叠测试不相加。
- 精确区分 selected model、provider call、计量、反馈、WordPress 保存，维护 Cloud 运行证据与 WordPress 最终真相的边界。
