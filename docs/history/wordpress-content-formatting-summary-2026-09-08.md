## 一、当前结论

项目由一人借助 AI 开发，时间与精力有限。当前应停止扩展语义分段实验，保留并收尾已经验证的规则型正文整理功能。

优先级固定为：

1. 已有功能可靠收尾。
2. 在日常使用中修复反复出现的问题。
3. 有明确收益证据后，再考虑语义分段。

暂停不是删除代码或放弃整理功能，也不是宣布现有候选已经合并、上线。已有研究、试验工具和失败记录保留，不自动启动下一轮实验。

## 三、始终保留的边界

- WordPress 持有编辑、权限及最终保存、发布权。
- Cloud 执行整理并返回结果，不直接写 WordPress，也不成为第二控制面。
- Cloud Addon 负责连接与签名传输，不另建整理引擎。
- Toolbox 提供入口、独立校验、编辑器显示与撤销。
- eval-lab 只提供开发期样本、检查及对比证据，不进入生产插件运行时，不授予写入权限。
- 计费使用第三方平台现有能力，不为这项任务另建计费系统。
- 自动评测由开发侧承担；用户只做实际使用与问题反馈，不承担逐篇打分工作。
- Gemini Nano 完全排除于当前开发范围。

## 四、推进过程及重要纠偏

### 1. 两站连接与技术验证

历史上先配置两套本地 WordPress 与 Addon，验证连接及 `technical_monitoring_only`。

- 站点 A：`magick-ai.local`。
- 站点 B：`magick-toolbox.local`。
- 用户提出使用蒲公英私网访问 M4；后续已有相关预览连接路径。
- 技术监测仅用于证明传输、去重、隔离和恢复，不等于模型质量已经得到验证。

已有计划记录了两站 Fake Provider 浏览器验证，以及真实签名元数据传输、去重和站点身份隔离验证。Fake Provider 不能证明真实模型质量；监测成功也不能替代正文整理的编辑器验收。

连接配置及网络地址是环境事实，不是长期可用承诺。以后操作前应重新核对，不在总结文档中保存账号凭据或密钥。

### 2. 从研究平台收敛到实际使用入口

过程中讨论过网页点选、候选预览、自动评分和多模型比较。用户随后反复明确：

> 在 WordPress 点击整理按钮，直接在正文编辑界面查看整理后的效果。

因此，独立候选网页、额外 Apply 步骤以及让用户逐项评审的流程，不再作为当前交付目标。eval-lab 留在开发侧，不能反过来增加用户的使用负担。

### 3. 从“文字间距调整”补齐到“正文结构整理”

用户在文章 2701 使用时报告过错误，也指出整理结果与参考效果不一致。此前实现及验证覆盖不足，不能用后台测试通过解释为用户要求已满足。

历史修复与复核记录包括：HTMLParser 的位置方法与内部 `offset` 字段冲突、WordPress 原生列表默认属性导致误拒绝、受保护内容 no-op 被误判，以及真实区块序列化和撤销行为的兼容问题。

由此形成的交付要求是：后端测试之外，必须验证真实 WordPress 编辑器中的显示、原生区块有效性、重复整理、撤销、等待期间编辑与失败保护。只看到“请求成功”或“增加了空格”不能证明结构整理有效。

### 4. 保真要求进一步明确

用户明确要求：

1. 原始图片、表格和文字不能删除，原始内容尽量不更改。
2. 中英文之间增加空格。
3. 合理分段。

此后以内容保留优先，不自动纠正措辞、事实、品牌名、大小写、标点、数字或单位，也不把历史迁移项目中的清理、删除操作直接移植到 WordPress。

## 五、最终实现方式

```text
WordPress 点击“整理”
  -> 当前正文及原文 SHA 经 Addon 签名发送
  -> Cloud 执行确定性间距及有限结构规则
  -> 返回完整整理正文及校验信息
  -> WordPress 独立校验，确认正文没有在等待期间改变
  -> 一次可撤销操作更新可见编辑器
  -> 用户自行使用 WordPress 原生保存或发布
```

没有额外候选页面或第二次 Apply 操作。工具不调用后台保存、发布，也不重新定义 WordPress 原生自动保存行为。

### 已做的规则

- 在可安全处理的文本中，为中文与英文字母、数字之间补空格。
- 对明确的连续标签链接及价格等元数据尾部，进行有限的原生列表转换。
- 在已存在重复 BR/星号列表上下文时，修复明确缺失的换行；不全局替换星号。
- 对超过约 180 个非空白字符的段落检查安全分段，而不是按 180 字硬切。
- 只在完整句末考虑切分，保留引号和括号；不使用逗号或任意空白作为兜底断点。
- 分段规则要求每侧至少两个完整句子和一定正文长度，避免一句一段及短小孤段。
- 支持有限的加粗、斜体、链接及行内代码结构；只有行内标签已全部闭合的位置才能分段，不复制或重新打开标签。
- 原有段落不合并。复杂、未知、带特殊属性或无法安全处理的结构保守跳过。

### 内容保护

- 依据原始位置切片和插入，不让模型重新生成整篇 HTML。
- 保留受保护的图片、表格、代码、链接和区块内容及顺序。
- WordPress 校验结果格式、原文/候选 SHA、文字顺序、属性及受保护内容。
- 结果不能还原为有效原生区块时拒绝应用。
- 未改动区块尽量保留原身份；新增分段可获得新身份。
- 请求期间发生后续编辑时，迟到结果不能覆盖新编辑。
- 失败或校验不通过时保留原文；支持原生撤销、重做和“撤销本次整理”。

“保真”是必须验证的约束，不是对任意未知 HTML 的兼容承诺。保守跳过或拒绝应用是设计的一部分。

### 接口状态

- WordPress 当前使用 `content_format_request.v2`，接收完整 `content_format_candidate.v2`。
- v2 整理路径为 HTML，返回 `structural_changes`；`inserted_spaces` 只计算间距插入，不等于整个 HTML 的字节变化。
- v1 保留早期间距整理兼容路径，包括 HTML/Markdown。不能因此声称当前已完成 Markdown 的全部结构整理或多平台交付。
- 默认整理运行时没有模型或向量调用，正文按 `no_store` 处理。
- “模型仅返回句子编号”只属于语义实验的内部方案，不意味着 WordPress 需要接收语义操作计划并自行整理。

## 七、语义分段试验与停止决定

### 为什么做试验

规则可以保证有限操作的确定性，但难以判断论点、例子、转折与主题变化。向量可以提供相似度信号，却不能单独判断“这里是否应另起一段”。

因此只在 eval-lab 比较，不先建设向量数据库，也不先把语义方案接入默认按钮。

### 实际执行

- 4 组原有博客文章的相邻段落：10946、12710、13105、19641。
- 仅在忽略的评测样本中临时合并原段落，再比较恢复边界；源文件与 WordPress 原文不变。
- 原作者分段作为参考，不是独立人工 gold，也不是唯一正确答案。
- 对比规则、相邻两句窗口向量、JSON 句子编号模型建议。
- 使用 M4 已安装的 `qwen3-embedding:0.6b` 与 `qwen3.5:9b`。
- 共 11 次本地推理请求，总耗时记录 99.62 秒；无模型下载、无付费 Provider 调用、无向量数据库。

| 方案 | 通过断点校验且重复稳定 | 原分段边界平均 F1 | 观察 |
| --- | --- | --- | --- |
| 规则 | 4/4 | 0.375 | 稳定，但受长度规则影响明显 |
| 窗口向量 | 4/4 | 0.500 | 部分改善，另一组从原来的两段拆为五段 |
| 本地文本模型 | 1/4 | 不作可比汇总 | 两组结果校验失败，一组重复处理后继续增加断点 |

向量请求记录约 1–44 秒；成功文本模型的首次请求约 5–24 秒。其耗时包含 SSH、模型加载和运行影响，与规则函数的本地耗时不能作严格横向排名。

这些结果只支持“当前组合不足以替换默认规则”，不支持“所有模型都不适合语义分段”或“向量已证明有普遍收益”。结构检查得 100 分也不代表阅读体验得到 100 分。

### 最终取舍

进一步投入的潜在收益是部分文章分段更自然；代价包括模型适配、等待时间、样本维护、异常处理及回归测试。对单人开发来说，当前没有足够证据证明这部分收益大于持续维护成本。

用户已经同意暂停下一阶段语义研发。更大样本、候选断点约束及更强模型都只保留为未来可选方向，不是自动执行的下一阶段任务。

## 九、后续只保留最小收尾清单

本次“收尾”完成的是历史归纳和本地落盘，不把未做的源码集成写成完成。

需要正式接入主线时，使用独立、明确的提交合并任务：

1. 清点 Cloud、Toolbox、Addon、eval-lab 的改动，区分本功能与无关修改，不批量清空或全量暂存。
2. 按职责组织可审查的提交；保留 v1/v2 契约与不保存、不改原文的保护。
3. 对待提交的确切版本执行必要检查和 CI，不机械重复全部历史测试。
4. 合并后再从干净、当前 `master` 执行规定的 M4 promotion 与相关 smoke，才能宣称 accepted。
5. 生产发布另行按明确授权执行。

日常使用阶段不加监控平台或评分页面。用户只在遇到问题时提供文章位置、实际结果和期望结果，由开发侧复现并决定是否补测试。

重启语义优化需要同时具备：同类分段问题反复出现、人工修正明显占用时间、现有规则不容易安全解决，并且能提出有界的试验预算。偶发问题先人工调整，不因为工具或研究已经存在就继续投入。
