## 1. "间歇失败"先做本地确定性复现

CI 上跨运行时好时坏的失败，第一步永远是本地全量复跑对应文件，而不是比对
CI 轮次推断"flaky"。本轮 `test_admin_observation_windows.py` 本地一次复现
即得 10 失败/3 通过的确定性结论，直接否掉了"进程内污染/环境差异"两个高成本
假设。反之，仅凭 CI 轮次对比会把确定性失败误诊为 flaky（本轮实况）。

## 2. "空洞绿"是误诊的直接推手（规则已入 AGENTS.md）

分类器跳过无关车道是效率设计，但 push 轮的 `success` 因此不区分"验证过"与
"没看"。本轮把一条跳过了 backend 车道的 push 成功当成了"同代码早前跑绿"的
证据点，诊断方向被带偏。诊断前必须核对被比较运行里目标车道真的执行了
（AGENTS.md 已有对应条款，见 #1025）。

## 3. 产品有意变更 + 测试部分更新 = 漂移高发模式

#1012 放宽观察窗口约束时更新了 3 个测试文件中的 1 个，漏掉另外 2 个的
3 处边界断言。经验：改约束/契约类值时，**全仓扫同类断言**一次
（如 `grep -rn "721\|43201" tests/`），不要只改手头那个文件；修完后同样
扫一遍确认无第三处残留。

## 4. 定向选择的已知盲点形态：跨模块测试文件 + 拼写差异

`test_admin_observation_windows.py` import 四个兄弟测试模块、测五条路由，
按文件名/依赖的定向映射天然够不到它；映射表里的 `test_*observability_*.py`
通配也匹配不到 "observation" 拼写。已知盲点已显式补进
`select-pr-backend-tests.py` 并由 CI 契约钉住（#1024）。新增跨模块契约
测试时，同步检查它是否落在相关路由的映射条目里。

## 5. 标题选择型门禁的守卫写法

`--grep` 选标题的步骤会随测试改名/新增静默失去覆盖。两种守卫已验证：
（a）要求关键 spec 无过滤全量执行，契约断言其调用行不含 `--grep`（#1022）；
（b）要求 grep 每个备选项必须匹配到真实测试标题，改名即红（#1022）。

## 6. 流程操作要点（本轮五次完整走通）

- 发布器对基线新鲜度 fail-closed：多会话并行时 master 随时前移，发布前
  一律 fetch + rebase + 复跑窄门禁（#1022 被 #1021 插队即遇此拦截）；
- 非 bot 的在途 PR 视为合并车道持有者，等它 MERGED 再发布（本轮 #1021
  约 45 秒即合并，#1024/#1025 发布时车道空闲）；
- 借主仓 venv 跑任务工作树的 pytest：`ROOT` 按 `__file__` 解析，直接在
  任务工作树下执行即可；质量门禁用 `NPCINK_CLOUD_PYTHON_BIN` 覆盖；
- Playwright 本地运行会把 `frontend/next-env.d.ts` 再生出一行类型引用，
  收尾前恢复该生成文件，勿把工具痕迹留在共享工作树；
- squash 合并后判定集成只能以"PR MERGED"为准，逐分支核对后再清理本地与
  远端分支（发布器本身永不删分支，删除是合并后的独立动作）。
